## Clarifications

### Session 2026-07-14（brainstorm 階段逐題親決，摘錄影響 scope 者）

- Q: sys_access_log 有表、有讀端授權種子、但零寫入端（永遠空表）如何處理？ → A: 全做——本刀補寫入層（已認證請求每請求落一列）＋讀端＋介面分頁；不取「只建讀端空表上架」與「整包延後」兩案。
- Q: session_event（會話終止事件：踢除／撤銷／登出／閒置／重放）不在 ADR 0011 三表拍板內，上不上查詢介面？ → A: 上——第四資料源＋讀端授權增量種子；「這帳號 session 為什麼斷」的系統自動事件（閒置／重放／登出）只有此表能答。
- Q: 查詢能力 v1 是否含文字模糊搜尋？ → A: 含——帳號名／存取路徑部分比對，索引照 B-039 rev3 已驗證結論於本刀 schema 期落地（trigram）；操作稽核 payload 內容搜尋不做（YAGNI）。
- Q: 日誌清理（purge）拍多深？ → A: 執行面本刀建（手動、僅超管、時間水平線唯一形狀、下限守門、動作自落操作稽核）；保留天數政策不拍、B-016 續留（容量警示時再議自動化）。
- Q: 操作稽核 payload 內既存個資（電話／信箱）在稽核介面如何呈現？ → A: 顯示面打碼（讀端於後端遮蔽後才上 wire）；落庫面定調現況白名單（密碼雜湊／會話識別永不入列）為政策本體、不回溯清洗（收 B-044）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 超管能在稽核中心查詢四類日誌 (Priority: P1)

超級管理員自系統管理選單進入「稽核中心」頁，於同一頁的四個分頁檢視操作日誌（誰對哪張業務資料做了什麼變更、變更前後快照）、存取軌跡（誰在何時打了哪個功能路徑、結果為何）、登入嘗試（誰在何時自哪個位址嘗試登入、成敗）、會話事件（誰的 session 因何被終止）。每個分頁支援時間區間、各源專屬條件過濾、帳號名／路徑部分比對模糊搜尋與分頁瀏覽；操作稽核快照中的電話／信箱以打碼形式呈現。

**Why this priority**: 這是本刀的核心價值載體——「管理動作可稽核、登入行為可追查、會話斷因可解釋」，兌現 rev3 以來遞延的稽核讀端拍板（ADR 0011）；其餘故事（存取記錄、清理）都以此頁為呈現面。

**Independent Test**: 不需存取記錄與清理能力即可獨立驗證——以既有操作稽核／登入嘗試／會話事件的真實資料，逐分頁驗證列表、過濾、模糊搜尋、分頁與打碼渲染；選單三語與頁面可達性（超管可進、非超管不可見）。

**Acceptance Scenarios**:

1. **Given** 超級管理員已登入，**When** 展開系統管理選單，**Then** 「稽核中心」選單項以當前語言正確顯示（三語零原始鍵字面）、點擊進入四分頁頁面。
2. **Given** 稽核中心操作日誌分頁，**When** 以時間區間＋資料表名＋操作類型＋操作者條件查詢，**Then** 列表回符合條件的分頁結果、新到舊排列，欄位含時間、操作者、操作類型、標的資料表／識別與變更前後快照。
3. **Given** 操作日誌快照內含電話／信箱值，**When** 檢視，**Then** 該等值以打碼形式呈現（`0912345678 → 091****78`；`andy@example.com → a***@example.com`），介面與回應皆無原值。
4. **Given** 登入嘗試分頁，**When** 以帳號名部分字串（如「adm」）模糊查詢，**Then** 回傳帳號名含該字串的嘗試列（含成敗、來源位址、時間）。
5. **Given** 會話事件分頁，**When** 以事件類型（如「閒置」）過濾，**Then** 僅回該類事件；列表呈現當事使用者（識別＋可解析時的帳號名）、事件類型、原因、時間。
6. **Given** 任一分頁的搜尋條件留空（空字串），**When** 查詢，**Then** 空字串等同未設該條件（不因空字串致整頁落空或請求錯誤）。
7. **Given** 非超級管理員角色登入，**Then** 稽核中心選單不可見；直接呼叫四支查詢能力 100% 得權限拒絕。

### User Story 2 - 系統記錄已認證使用者的存取軌跡 (Priority: P2)

已認證使用者（管理者）每次呼叫受保護功能，系統自動記錄一筆存取軌跡：誰、何時、以何方法打了哪個功能路徑、結果狀態碼、來源位址（信任錨還原）。記錄行為對使用者完全透明、絕不影響業務請求成敗；記錄內容不含請求內文與查詢字串（零個資落庫）。

**Why this priority**: 存取日誌分頁的資料源——不啟用寫入則該分頁永遠空表（D1 親決全做）。它把「管理者在後台做過什麼」的可觀察面自「有變更的寫操作」擴展到「所有存取」。

**Independent Test**: 以已認證身分呼叫任意受保護端點後，於存取日誌分頁（或資料層）驗證恰一列新記錄且欄位正確；以未認證身分呼叫公開端點驗證零記錄；模擬記錄故障驗證業務請求不受影響。

**Acceptance Scenarios**:

1. **Given** 已認證的超級管理員，**When** 呼叫任一受保護功能（含稽核中心自身的查詢），**Then** 恰產生一筆存取軌跡（方法、路徑、狀態碼、操作者、來源位址、追蹤識別俱全）。
2. **Given** 未認證訪客，**When** 呼叫公開功能（如登入），**Then** 不產生存取軌跡（登入行為由登入嘗試稽核涵蓋、不重疊）。
3. **Given** 存取軌跡寫入故障（如儲存暫時不可用），**When** 使用者呼叫受保護功能，**Then** 業務請求照常成功（fail-open）、故障僅內部告警。
4. **Given** 帶敏感內文的請求（如重設密碼），**When** 存取軌跡落地，**Then** 記錄僅含方法／路徑／狀態碼等中性欄位，不含請求內文與查詢字串。

### User Story 3 - 超管能以時間水平線清理過期日誌 (Priority: P3)

超級管理員於任一稽核分頁點「清理」，輸入天數（如 90 天）並二次確認後，系統刪除該資料源中「N 天前」的全部記錄並回報刪除筆數。清理只能以時間水平線整段刪除、無法挑選特定記錄；天數有下限守門（30 天）；每次清理本身留下一筆操作稽核（含資料源、天數、刪除筆數），且清理稽核紀錄永久保留——不被任何後續清理刪除（滅證鏈可追溯）。

**Why this priority**: 四張日誌表單調成長（存取記錄啟用後尤甚），清理是空間治理的最低必要手段；水平線唯一形狀＋自落稽核防止「選擇性滅證」。依賴 US1 的頁面為入口。

**Independent Test**: 對含新舊資料的日誌表執行清理，驗證僅水平線前記錄被刪、近期記錄保留；低於下限的天數被拒並回專屬訊息；清理後操作日誌分頁可查到該次清理的稽核列。

**Acceptance Scenarios**:

1. **Given** 某日誌源含 100 天前與 10 天前的記錄，**When** 以 90 天執行清理並確認，**Then** 100 天前的記錄全數刪除、10 天前的記錄完整保留，回報刪除筆數。
2. **Given** 清理天數輸入 7（低於下限 30），**When** 提交，**Then** 被拒並回專屬訊息（下限守門）、資料零變更。
3. **Given** 清理成功完成，**When** 於操作日誌分頁查詢，**Then** 可見該次清理的稽核列（含資料源、天數、刪除筆數）。
4. **Given** 清理範圍內零筆記錄，**When** 執行清理，**Then** 操作成功、回報刪除筆數 0，照落操作稽核（管理動作有案可查）。
5. **Given** 任何呼叫方，**Then** 系統不存在「刪除指定單筆／指定條件稽核記錄」的能力（構造上僅水平線＋固定類型豁免）。
6. **Given** 操作日誌中存在已逾水平線的歷次清理稽核列，**When** 對操作日誌執行清理，**Then** 該等清理紀錄 100% 保留、其他逾期列正常刪除。

### User Story 4 - 稽核記錄完整且不灌水 (Priority: P4)

管理動作必留痕：手動解鎖登入鎖定的動作記錄改為「先記錄、後生效」——稽核記錄落定後才解鎖，消滅「解鎖生效但零稽核列」的縫隙。會話閒置事件收斂為冪等：同一 session 的閒置逾時僅記錄首次，背景自動換發造成的重複閒置事件不再灌水。

**Why this priority**: 稽核頁的價值以資料可信為前提——查得到（完整）且查得準（不灌水）。兌現 B-077 與 B-093 兩筆跨刀承諾；依賴 US1 呈現治理成效。

**Independent Test**: 解鎖流程模擬稽核寫入故障，驗證解鎖不生效（回內部錯誤）、重試成功後恰有記錄；對同一 session 觸發多次閒置逾時，驗證會話事件僅一列。

**Acceptance Scenarios**:

1. **Given** 手動解鎖操作，**When** 稽核記錄寫入失敗，**Then** 解鎖不生效、回內部錯誤（管理者可重試）；0% 出現「已解鎖但無稽核列」。
2. **Given** 手動解鎖操作，**When** 稽核記錄寫入成功但解鎖生效步驟失敗，**Then** 回內部錯誤；留存的稽核列記錄該次嘗試（重試產生新列可接受）。
3. **Given** 某 session 已因閒置逾時被記錄一筆會話事件，**When** 其背景換發再次觸發閒置逾時，**Then** 不再新增會話事件列（同 session 恰一列閒置事件）。
4. **Given** 既有登入終局稽核語意（僅密碼雜湊實際驗證的終局落恰一列、節流短路零列），**Then** 本刀零改動（回歸驗證）。

### User Story 5 - 介面在地化與拒因明細 (Priority: P5)

稽核中心全部介面文案（選單項、分頁標題、欄位、清理對話框、拒因訊息）三語齊備；清理下限違反等拒因以結構化明細呈現具體原因。登入嘗試分頁明示資料語意（節流短路的拒絕不在此表），防管理者誤判漏記。

**Why this priority**: 兌現 B-061 audit 項（manage_audit 選單原始鍵字面已存在兩刀、CDP 兩度驗證仍在）；語意說明防止稽核資料被誤讀。

**Independent Test**: 三語切換逐語驗證選單／頁面／拒因零原始鍵字面；觸發清理下限拒因驗證明細呈現；登入嘗試分頁語意說明可見。

**Acceptance Scenarios**:

1. **Given** 三種語言逐一切換，**When** 檢視稽核中心選單與四分頁，**Then** 全部文案正確在地化、零原始鍵字面。
2. **Given** 清理天數低於下限，**When** 提交，**Then** 拒因訊息以當前語言呈現具體明細（含下限值插值）。
3. **Given** 登入嘗試分頁，**Then** 介面呈現資料語意說明（節流短路的拒絕不落此表）。

### Edge Cases

- **打碼異常值**：電話值長度不足以「留前 3 後 2」（≤5 字元）→ 全遮為 `****`；信箱值不含 `@` → 照 local-part 規則（首字元＋`***`）；非字串型值（數值／null）→ 原樣不打碼（僅字串值適用規則）。規則為封閉定義、無「無法打碼即洩原值」路徑。
- **打碼鍵通用性**：打碼以鍵名（`user_phone`／`user_email`）為準、涵蓋快照前後兩側與任何資料表來源——未來新資料表快照含同名鍵自動受打碼涵蓋。
- **時間區間起訖顛倒**（起 > 訖）：回空結果（區間語意自然為空、不設專屬拒因）。
- **清理水平線與新寫入併發**：清理刪「N 天前」、新記錄時間為現在——兩者構造上無交集；清理自身的稽核列恆不落入本次刪除範圍；歷次清理稽核列受固定類型豁免（FR-012）。
- **清理目標非法**（資料源不在四表白名單）：拒絕、專屬訊息、零變更。
- **登入嘗試分頁語意**：節流短路（超限即拒）與內部錯誤路徑零稽核列＝既有 by-design；本刀不改寫入語意、僅於介面明示（US5）。
- **會話事件來源位址現形**：該表位址欄為既有單欄字串形（非信任錨四欄組），照現形回傳呈現、本刀不改結構。
- **帳號名解析（顯示側）**：操作者／當事者欄以識別為權威，可解析時附帳號名（含已軟刪使用者）；解析不到（如已清理的孤兒識別）→ 介面顯示識別、不報錯。
- **帳號名解析（過濾側）**：人員過濾傳帳號名時，同名已軟刪多帳號→識別集合全部納入；解析零命中→空結果（非錯誤）；帳號名與識別同時傳入→以識別為準、忽略帳號名（寬鬆語意、不設新拒因）。
- **存取軌跡中的請求中止**：回應未完成（連線中斷）的請求記錄依 best-effort 語意可缺席——存取軌跡非計費級完整性承諾（明文接受）。
- **模糊搜尋特殊字元**：搜尋字串含萬用字元字面（`%`／`_`）時作字面比對處理、不得注入查詢語意。

## Requirements *(mandatory)*

### Functional Requirements

#### 稽核中心查詢（US1）

- **FR-001**: 系統 MUST 提供四支稽核查詢能力（操作日誌／存取日誌／登入嘗試／會話事件），各 MUST 分頁（分頁形狀對齊既有列表範式）、預設新到舊排列（同時刻以識別遞減決勝、順序穩定）。
- **FR-002**: 四源 MUST 支援時間區間過濾（閉開區間〔含起、不含訖〕）；各源專屬過濾 MUST 為——操作日誌：標的資料表等值、操作類型等值、操作者（人員過濾）；存取日誌：方法等值、狀態碼等值、操作者（人員過濾）；登入嘗試：成敗等值、來源位址等值；會話事件：當事使用者（人員過濾）、事件類型等值、原因等值。**人員過濾** MUST 接受帳號名或識別擇一傳入：識別走等值；帳號名由服務端解析為識別集合（含已軟刪同名者全部——稽核鏈不因刪帳號而斷；解析零命中回空結果、非錯誤），前端 MUST NOT 自行解析。全部搜尋參數 MUST 以「空字串／缺席等同未設」處理。
- **FR-003**: 模糊搜尋 MUST 涵蓋登入嘗試的帳號名與存取日誌的路徑（部分字串比對、大小寫不敏感）；支撐索引（trigram）MUST 於本刀 schema 期落地；操作稽核快照內容搜尋 MUST NOT 交付（明文不做）。模糊字串含萬用字元字面 MUST 作字面處理。
- **FR-004**: 操作日誌回應中快照（前後兩側）的電話／信箱鍵值 MUST 於後端遮蔽後才輸出（前端 MUST NOT 經手原值）：字串值電話留前 3 後 2、中段固定 `****`（不保留原長度）；信箱 local-part 留首字元＋固定 `***`、網域全留；電話值 ≤5 字元全遮；信箱值無 `@` 照 local-part 規則；非字串值原樣。打碼以鍵名為準、對任何資料表來源通用。
- **FR-005**: 四源回應 MUST 逐欄構造（不序列化原始資料列）；操作者／當事者欄 MUST 以識別為權威並於可解析時附帳號名（含已軟刪使用者；解析不到顯示識別）。回應時間欄 MUST 帶時區偏移的完整時刻格式，且本刀 MUST 一併兌現既有時間欄上 wire 的格式守門義務（B-091——涵蓋既有已上 wire 的時間欄斷言重建）。
- **FR-006**: 四支查詢與清理能力 MUST 僅授權超級管理員。三支查詢的存取政策已預埋於凍結種子（沿用不變更）；會話事件查詢與清理兩項 MUST 由顯式增量種子遷移新增授權（恰 2 列）、MUST NOT 改寫凍結種子；對外註冊的方法動詞 MUST 與政策逐條一致。
- **FR-007**: 四支查詢 MUST 為純唯讀——查詢處理 MUST 零業務寫入、零狀態變更（存取軌跡記錄由統一記錄層承載、非查詢處理職責）。

#### 存取軌跡記錄（US2）

- **FR-008**: 系統 MUST 記錄已認證請求的存取軌跡：每一已認證請求恰一列（方法、路徑、狀態碼、操作者、來源位址信任錨組、地域標註 best-effort、追蹤識別）；於回應完成後記錄。
- **FR-009**: 存取軌跡記錄 MUST 為 best-effort fail-open——寫入失敗僅內部告警、MUST NOT 影響業務請求成敗與延遲語意；回應未完成（連線中斷）的缺席明文接受。
- **FR-010**: 存取軌跡 MUST NOT 記錄請求內文與查詢字串（零個資落庫）；未認證請求 MUST NOT 記錄（登入行為由登入嘗試稽核涵蓋）。
- **FR-011**: 記錄範圍 MUST 無豁免名單——稽核中心自身的查詢請求照記（一致性）。

#### 水平線清理（US3）

- **FR-012**: 系統 MUST 提供稽核清理能力：參數為資料源（限四稽核表封閉白名單）與天數；語意 MUST 為時間水平線整段刪除（刪除「N 天前」全部記錄）——系統 MUST NOT 存在挑選特定記錄或任意條件刪除稽核資料的路徑（構造上防選擇性滅證）。唯一固定排除：操作日誌源的水平線刪除 MUST 豁免操作類型為清理的稽核列（日誌刪除的後設證據永久保留）——此為封閉類型排除、MUST NOT 擴為任意條件排除。
- **FR-013**: 清理天數 MUST 有下限守門（30 天、服務端常數）；低於下限 MUST 拒絕並回結構化拒因（含下限值插值）、零變更。保留天數政策與自動化排程 MUST NOT 於本刀拍定（B-016 續留）。
- **FR-014**: 每次清理 MUST 自落一筆操作稽核（操作類型為清理專屬類型、內容含資料源／天數／刪除筆數）；刪除筆數為 0 照落（管理動作有案可查）；清理稽核列（本次與歷次）MUST 永不被任何清理刪除（FR-012 固定豁免；本次自身亦因水平線語意天然不落範圍）。
- **FR-015**: 清理介面 MUST 於每分頁提供入口、以確認對話框二次確認（含天數輸入與後果說明）後才執行。

#### 稽核資料品質（US4）

- **FR-016**: 手動解鎖動作序 MUST 為「稽核先於生效」——操作稽核於權威儲存落定成功後才執行解鎖生效步驟；稽核寫入失敗 MUST 中止解鎖並回內部錯誤（可重試）；生效步驟失敗亦回內部錯誤、已落稽核列記錄該次嘗試（重試產生新列明文接受）。「解鎖生效但零稽核列」MUST 為構造上不可達。
- **FR-017**: 會話閒置事件 MUST 冪等——同一 session 的閒置逾時恰記錄一列（首次）；重複觸發（如背景自動換發）MUST NOT 新增列。冪等標記故障時 MUST 傾向少記不多記（維持既有 best-effort 稽核語意、不影響換發回應）。
- **FR-018**: 既有稽核寫入語意 MUST 零改動：登入終局「恰一列」（短路零列）、業務寫與操作稽核同交易、撤銷連動的會話事件語意——本刀讀端與品質補強 MUST NOT 觸碰上述寫入面之外的行為（回歸保證）。

#### 在地化與拒因（US5）

- **FR-019**: 稽核中心選單三語譯文 MUST 隨建頁一併交付（route 譯文鍵不得獨立新增——與頁面同交付；兌現既有選單殼的原始鍵字面缺口）。
- **FR-020**: 頁面級文案（分頁標題、欄位、清理對話框、語意說明）與拒因訊息鍵 MUST 三語齊備、型別定義與譯文同交付；一因一鍵（清理下限、非法資料源等各有專屬鍵）、需要參數者經既有明細通道下發插值。
- **FR-021**: 登入嘗試分頁 MUST 呈現資料語意說明（節流短路拒絕不落此表——既有 by-design 語意的介面明示）。

#### 資料治理與邊界

- **FR-022**: 本刀 MUST NOT 變更資料表結構（零建表、零加欄、零改型）；schema 期交付 MUST 恰為：模糊搜尋索引擴充（含所需資料庫擴充套件啟用）＋授權增量種子 2 列＋一次性資料清理（FR-023）。
- **FR-023**: 本刀 MUST 一次性清理憑證表的歷史孤兒列（擁有者識別已不存在於使用者表者；測試殘留）；清理 MUST NOT 影響任何擁有者仍存在的列。
- **FR-024**: 本刀 MUST NOT 新增任何錯誤碼；回應信封結構 MUST 維持凍結。
- **FR-025**: 本刀 MUST NOT 交付：稽核資料匯出（CSV 等）、操作稽核快照內容搜尋、自動化清理排程、非超管的稽核讀取授權下放、按鈕級授權代碼（整頁以選單政策供裝——後續下放需求另刀議）。
- **FR-026**: 稽核寫入輔助能力的模組可見性 MUST 收斂為套件內部（讀端新增之列表能力除外）——既有跨刀承諾的順手兌現，MUST NOT 改變任何呼叫方行為。

### Key Entities

- **操作日誌**：管理動作的不可竄改流水——時間、操作者、操作類型、標的資料表／識別、變更前後快照（快照含既存個資、顯示面打碼）、來源位址信任錨組、追蹤識別。**結構凍結、本刀零變更**；本刀新增清理專屬操作類型值與讀取面。
- **存取軌跡**：已認證請求的存取流水——時間、操作者、方法、路徑、狀態碼、來源位址信任錨組、地域、追蹤識別。結構凍結；本刀交付其**第一個寫入端**與讀取面。
- **登入嘗試**：登入終局的稽核流水——時間、嘗試帳號名、成敗、來源位址、地域、追蹤識別；寫入語意既有且零改動（恰一列／短路零列）；本刀交付讀取面與帳號名模糊索引。
- **會話事件**：session 終止事件流水——時間、當事使用者、session 識別、事件類型（踢除／撤銷／登出／閒置／重放）、原因、操作者；本刀交付讀取面＋閒置事件冪等補強。
- **登入鎖定稽核（解鎖動作）**：既有解鎖能力的操作稽核——本刀改其動作序為稽核先於生效。
- **憑證列（旁及）**：非稽核源；本刀僅一次性清理其歷史孤兒列、不提供其查詢面。

## Assumptions

### 既有資產（已核實、2026-07-14 三路偵察）

- **四源資料表全在凍結基線**（結構零變更）：操作日誌（七個子系統已寫入、同交易接縫既有）、存取軌跡（表在、零寫入端＝本刀補）、登入嘗試（寫入既有、僅節流計數消費）、會話事件（五類事件寫入既有）。時間類查詢索引四表齊備；模糊索引（trigram）缺＝本刀 schema 期補。
- **選單殼與三支查詢授權已預埋**（凍結種子）：稽核中心選單項＋操作日誌／存取軌跡／登入嘗試三支查詢政策；選單三語譯文缺（原始鍵字面已存在、兩刀 CDP 驗證在案）；會話事件查詢與清理授權全新＝增量種子。
- **查詢面現況＝零**：四源皆無管理查詢能力（僅節流計數聚合與測試輔助）——本刀為讀端全新地。
- **快照個資現況**：密碼雜湊與會話識別已被白名單構造結構性排除（負向自證在案）；電話／信箱等一般個資自 011 起既成落庫——顯示面打碼為本刀新增、落庫面不回溯。
- **前端範式可循**：管理頁分頁表格與唯讀搜尋卡範式既有；時間區間選擇器為全庫首次引入（風險列管）；新頁走既有「新增檔案軌道」慣例（凍結檔零改動）。

### 設計取捨（有意識接受）

- **存取軌跡非完整性承諾**：best-effort fail-open——寫入故障或連線中斷時允許缺列，換取「絕不影響業務請求」；稽核完整性的強承諾僅及操作稽核（同交易）與解鎖（稽核先於生效）。
- **保留天數政策不拍**：本刀僅建清理機制與 30 天下限；「多久算夠」缺乏量級資料依據、待容量警示時以真實成長速率再拍（B-016 續留）——機制先行、政策後定（rev3 結論沿用）。
- **打碼僅及稽核讀端**：使用者管理頁等既有介面的個資顯示語意不變——同一超管兩頁所見不同為有意識接受（稽核頁定位為可長期翻閱／未來可能下放的報表面、防旁窺基線較高）。
- **解鎖重試可產生多列嘗試紀錄**：稽核先於生效的代價——生效步驟失敗後重試會再落一列；「多記嘗試」優於「生效無記錄」。
- **閒置事件冪等傾向少記**：冪等標記故障時跳過記錄（不多記）、維持既有 best-effort 語意——會話事件表非強完整性面。

### 治理（隨刀落地）

- **ADR 0057~0060（draft 已隨 brainstorm 落地）**：四源讀端＋查詢能力（增補 ADR 0011、非翻案）／清理水平線執行面／個資打碼政策（收 B-044）／存取軌跡寫入端啟用——plan 期轉 accepted。
- **憲法新島 J（稽核域）候選、MINOR 版本升級**（措辭 plan 期定稿）：J1 稽核讀端 read-only＋僅超管；J2 存取軌跡記錄 fail-open 絕不擋業務請求；J3 清理唯一形狀＝時間水平線＋自落操作稽核＋清理紀錄固定豁免（構造上禁選擇列刪、後設證據永久保留）；J4 個資顯示打碼單點（讀端後端遮蔽、前端不經手原值）；J5 解鎖稽核先於生效。
- **前端軌道授權擴展點（前端執行單元前經 user 親決）**：①一頁四分頁佈局（超出既有「嚴格鏡像 user/role/menu 結構」字面——既有管理頁皆單表格頁）；②清理確認對話框（新維運動作對話框、比照 011 解鎖對話框先例）；③時間區間選擇器（新表單控件、全庫首次）。其餘接線（列表接真、搜尋卡、i18n）落既有授權軌道。
