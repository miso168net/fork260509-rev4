## Clarifications

### Session 2026-07-06

- Q: 盜用（reuse）偵測觸發時的撤銷範圍——只撤被盜會話 vs 該使用者全部會話？ → A: **只撤該被盜會話**（其 `rotation_chain` token family）——本人＋竊者於該會話雙雙登出；該使用者其他會話不受影響（OAuth rotation 標準、proportionate，非「帳號全域受損」假設）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 憑證輪替與盜用偵測（refresh 被竊不再無限續命） (Priority: P1)

登入後只要持續使用，會話憑證於每次續命自動輪替（舊憑證作廢、發新憑證），使用者零感知。
若某枚已作廢的舊 refresh 憑證再度被呈遞（＝典型盜用重放：竊者與本人各持一份），系統判定盜用、
**撤銷整條會話**——本人與竊者雙方下一個動作皆被登出，安全優先。合法的並發續命（同一分頁多請求、
網路重試、雙請求棧）不得被誤判為盜用。

**Why this priority**: 這是本刀存在的頭號動機——關掉 005 明示接受的「refresh 憑證被竊可無限續命」
缺口（張力1、ADR 0030）；沒有它，被竊憑證永遠可續命、無偵測無撤銷。

**Independent Test**: 後端實測換發端點——連續正常續命不斷線（輪替透明）；呈遞已作廢舊憑證→整條會話撤、
雙方 `8888`；並發呈遞同一有效憑證（兩請求）→一成功、另一得既發後繼或良性放行、會話**不被撤**。
CDP 實機：正常操作跨續命邊界零中斷；雙分頁並發不誤登出。

**Acceptance Scenarios**:

1. **Given** 已登入且持續操作，**When** 憑證於續命點輪替，**Then** 前端無感換發新憑證對、原操作照常
   完成、會話延續；舊憑證即刻作廢、不可再用。
2. **Given** 一枚已被輪替作廢的舊 refresh 憑證（模擬竊取後重放），**When** 以它呼叫換發，**Then** 系統
   判定盜用、撤銷整條會話所有憑證＋落一列稽核（event=reuse）；該會話任何後續請求一律 `8888` 登出。
3. **Given** 同一枚仍有效的 refresh 憑證被兩個並發請求同時呈遞（合法並發/網路重試），**When** 兩者近乎
   同時到達換發端點，**Then** 一者輪替成功、另一者於極短寬限窗內被判良性並冪等取得既發後繼（或放行）、
   **會話不被撤銷**、使用者不被登出。
4. **Given** 已作廢舊憑證於寬限窗**之外**再現、或呈遞更早世代的憑證，**When** 換發，**Then** 判盜用、
   撤整條會話、`8888`。

### User Story 2 - 單一會話政策（他處登入即時踢除） (Priority: P1)

當「單一會話」政策對某帳號生效時，該帳號在新裝置登入會**踢除其既有的其他會話**：被踢會話的下一個
動作收到阻斷式提示「已在他處登入」並回登入頁。政策以**全域預設＋每使用者覆寫**解析（全域開關
`single_session_default`，每使用者可 `inherit`／強制 `single`／強制 `multi`）；政策關閉時放行同帳號
多裝置並存。

**Why this priority**: rev3 對此維度改向三次（永遠踢舊→政策感知→即時硬撤）的震央——B-021 要求一次
設計完整、不再翻案；消費 005 凍結預留的 `7777`（他處登入）碼位。

**Independent Test**: 後端實測——政策 on 時，同帳號第二次登入使第一個會話進撤銷集、其下次請求得 `7777`；
政策 off 時多會話並存不互踢；每使用者覆寫（single/multi/inherit）解析矩陣正確；踢除**不誤傷**當次
新建的會話。CDP 實機（CDP-1）：切全域為 on→瀏覽器 A 登入→B 同帳號登入→A 下次請求彈阻斷 modal
「已在他處登入」。

**Acceptance Scenarios**:

1. **Given** 全域 `single_session_default`＝on（或該帳號覆寫＝single），**When** 同帳號在第二裝置登入，
   **Then** 第一個會話被列入撤銷、其下次任一請求回 `7777`（阻斷式 modal「已在他處登入」）並回登入頁；
   新登入的會話正常可用（不誤傷）。
2. **Given** 全域＝off 且帳號覆寫＝inherit（或＝multi），**When** 同帳號在多裝置登入，**Then** 各會話
   並存、互不踢除。
3. **Given** 帳號覆寫＝single 而全域＝off，**When** 該帳號多裝置登入，**Then** 仍單一會話（每使用者覆寫
   優先於全域）；其他 inherit 帳號則放行多會話。
4. **Given** 全域政策於 runtime 由 off 改 on，**When** 已存在多個並存會話，**Then** 既存會話**不被回溯
   踢除**（政策僅對後續登入求值、by-design）；新登入起套用單一會話。

### User Story 3 - 伺服器端登出與即時撤銷 (Priority: P2)

使用者主動登出時，會話於**伺服器端**即刻失效——即使登出時 access 憑證已過期亦然；被擷取的 refresh
憑證登出後不可再續命。系統對撤銷即時感知（近即時、非等憑證自然過期）。本刀並建立通用「撤銷該使用者
其他會話」能力（供未來改密／停用／管理員踢除接線）。

**Why this priority**: 關掉 005 張力2（停用/撤權殘留 ≤access TTL）；補齊 005 明示「無登出後端端點」的缺口
（Tier 3 下登出必須伺服器端撤銷、否則被竊憑證登出後仍可用）。

**Independent Test**: 後端實測登出端點（收 refresh 憑證身分→撤該會話→被擷取舊 refresh 再換發得 `8888`）；
access 過期後仍能登出撤銷；撤銷後受保護端點即時擋（近即時、非等自然過期）；撤銷 primitive 單元測試
（撤某使用者其他會話、保留當次）。CDP 實機（CDP-4）：登出→舊憑證換發失敗 `8888`；access 過期後登出仍撤。

**Acceptance Scenarios**:

1. **Given** 已登入使用者，**When** 主動登出（以 refresh 憑證身分），**Then** 該會話伺服器端撤銷、落稽核
   （event=logout）；前端清本地憑證回登入頁；該會話的 refresh 憑證再換發一律 `8888`。
2. **Given** 使用者閒置至 access 憑證已過期後才登出，**When** 送出登出，**Then** 仍能以 refresh 憑證身分
   撤銷伺服器端會話（不因 access 過期而撤不掉）。
3. **Given** 某會話已被撤銷（因登出／踢除／盜用），**When** 其持有的 access 憑證發起受保護請求，**Then**
   近即時被擋登出（撤銷後的誤放行窗上界為一個 access 憑證時效、屆時憑證亦自然過期）。
4. **Given** 「撤銷某使用者其他會話」能力（primitive），**When** 以〔使用者、保留會話〕呼叫，**Then**
   該使用者除保留會話外的所有活躍會話被撤、保留會話不受影響（供未來改密／停用／踢除端點接線）。

### User Story 4 - 精確閒置逾時（精確到分＋重登提示） (Priority: P2)

登入後只要持續操作就不被登出；閒置**恰滿 N 分鐘**後的下一個動作跳輕量提示「請重新登入」並回登入頁。
相對 005 的模糊界線（早登出可達一個 access 時效），本刀以伺服器端記錄最後活動時間，使閒置逾時精確到分。
N 由超級管理員在系統設定頁「工作階段設定」群組調整（預設 60 分）。

**Why this priority**: 關掉 005 張力3（登出界線 [N−access,N] 不精確）；因本刀引入 Redis，順勢把閒置一次
做完整（精確界線＝B-048「session 指標熱快取」的消費者到場）。

**Independent Test**: 後端實測——持續（valid）活動推進最後活動時間、閒置逾 N→換發 `8888`；換發本身**不**
推進最後活動時間（腳本 refresh-loop 無法繞過閒置）；熱快取失效時優雅降級為憑證時效為界、絕不誤踢活躍者。
CDP 實機（CDP-2）：設定調短→持續操作不登出→閒置滿 N 恰時登出＋「請重新登入」toast 後靜默重導。

**Acceptance Scenarios**:

1. **Given** 已登入且持續操作（每次真實請求推進最後活動時間），**When** 操作間隔皆小於 N，**Then** 永不
   閒置登出、續命透明。
2. **Given** 閒置恰滿 N 分鐘，**When** 下一個動作觸發換發，**Then** 換發被拒 `8888`、前端顯示輕量 toast
   「請重新登入」後靜默重導登入頁；登出點精確落在最後真實活動＋N（非提前）。
3. **Given** 一持有 refresh 憑證的背景腳本反覆呼叫換發端點（無真實使用者活動），**When** 閒置滿 N，**Then**
   換發仍被判閒置拒 `8888`（換發不推進最後活動時間、無法自我續命繞過閒置）。
4. **Given** 最後活動時間熱快取不可用（基建降級），**When** 換發，**Then** 退回以 refresh 憑證時效為界
   （界線變寬、偏晚登出），**絕不**誤踢仍活躍的使用者。
5. **Given** 超級管理員把 N 由 60 調小（範圍 5..=1440），**When** 既有會話下一次續命，**Then** 新窗以新 N 計
   （設定變更於下一次續命生效、承襲 ADR 0030）。

### User Story 5 - 會話撤銷稽核（安全可回溯） (Priority: P3)

每一次會話終止事件——他處登入踢除、盜用撤銷、主動登出、閒置逾時——都留下一列可回溯稽核（誰、哪個
會話、何原因、何時、來源），供 admin 安全後台事後追查。

**Why this priority**: 對 admin 安全後台，「A 帳號何時、因何原因、被哪個會話踢除/撤銷」是基本可追溯需求；
005 僅有登入嘗試稽核、本刀新增的撤銷事件全無軌跡（對抗式審查缺口 O）。

**Independent Test**: 後端實測——四類終止事件（kicked／revoked〔登出/盜用〕／idle／reuse）各落恰一列稽核，
欄含使用者、會話識別、事件型別、原因、時間、來源；查詢稽核表可還原一次撤銷的來龍去脈。

**Acceptance Scenarios**:

1. **Given** 任一會話終止事件發生，**When** 事件落地，**Then** 稽核表新增一列，含使用者、會話識別、
   事件型別（kicked/revoked/logout/idle/reuse）、原因、時間戳、來源（best-effort）。
2. **Given** 一次盜用撤銷整條會話，**When** 查詢稽核，**Then** 可辨識該撤銷的觸發原因與受影響會話。

### Edge Cases

- 同一枚有效 refresh 憑證的合法並發呈遞（雙分頁、網路重試、前端雙請求棧）→ 寬限窗內判良性、冪等回後繼、
  **不撤會話**；超窗或更早世代票→判盜用撤整條會話。
- 被單一會話踢除者，其 access 憑證此時通常已過期 → 走換發路徑亦須得 `7777`（他處登入），而非 `8888`
  （否則阻斷式「已在他處登入」提示永不出現）。
- 撤銷檢查的基建（熱快取）連線故障 → 退回權威資料源查詢（永遠正確、僅較慢），**不因基建故障而放行**已撤
  會話（fail-closed）；基建「查無此撤銷紀錄」＝權威判定「未撤」＝放行（blocklist 語意）。
- 撤銷後至撤銷紀錄寫入熱快取之間的短窗（含寫入失敗/程序崩潰）→ 誤放行上界＝一個 access 憑證時效
  （憑證自然過期＋換發恆查權威源），為有界曝險。
- 閒置逾時觸發時 access 憑證必已過期（access 時效 ≤ N×30 < 閒置門檻 N×60）→ 閒置拒發**不需**額外撤銷。
- 全域政策於 runtime 變更 → 僅對後續登入生效、既存會話不回溯（by-design）。
- N 於會話存續中被**調大** → 既有會話舊憑證時效較短、需一次續命後才完整套用新窗（過渡期最短保護仍受
  舊憑證時效限制）；「絕不誤踢」限於穩定 N＋基建降級語境。
- 換發路徑對任何失敗（過期／垃圾／驗證失敗／閒置拒）一律 `8888`，**絕不回** `3333/9999/9998`（防前端
  自動換發死迴圈）；唯他處登入踢除得 `7777`（阻斷式、不觸發自動換發）。
- base-web inline 改動漏 `rev4-inline`／修改型漏 `原行:` → fork-delta-lint 攔；toast 為攔截器控制流變更、
  逾既有軌道紅線→需新★軌道授權（ADR 0034）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 於換發端點實作**憑證輪替狀態機**：每次成功換發使呈遞的 refresh 憑證作廢、發放
  同一會話的新憑證對；會話憑證狀態落庫（每會話為一條輪替鏈；憑證以其確定性摘要為鍵、非加鹽雜湊，
  確保等值查得中）。輪替寫入須抗「撤銷穿插」競態（先讀後寫的發放決策必在鎖住的當前列上重判、L-075）。
- **FR-002**: 系統 MUST 實作**盜用（重放）偵測**：呈遞一枚已作廢（已輪替／已撤銷）的 refresh 憑證→判盜用
  →撤銷整條會話（該會話所有憑證作廢）＋落稽核（reuse）＋回 `8888`。撤銷須完整涵蓋並發輪替剛產生的
  後繼憑證（撤銷不得殘留任何仍可用憑證）。**撤銷 blast radius 限該被盜會話**（其 `rotation_chain` token
  family）、**不及**該使用者其他會話（clarify 2026-07-06；OAuth 標準、proportionate）。
- **FR-003**: 憑證輪替 MUST 對**合法並發/重試**保留寬限：呈遞一枚剛被輪替、且為當前有效憑證之直接前驅、
  且落在極短寬限窗（活書常數）內者，判良性並冪等回傳既發後繼（或放行）、**不撤會話**；僅超窗／更早世代／
  已撤銷者才判盜用。前端 refresh 去重須跨兩個請求棧共用單一在途承諾，避免雙棧各自觸發並發換發。
- **FR-004**: 系統 MUST 以**全域＋每使用者覆寫**解析單一會話政策：全域開關 `single_session_default`
  （enum on/off、已 seed off）＋每使用者 `session_policy`（`inherit`/`single`/`multi`）；有效單一會話＝
  `policy==single` 或（`policy==inherit` 且全域==on）。政策解析階層：每使用者覆寫優先於全域、`inherit`
  讀全域。（本刀**不**含每使用者覆寫的設定 UI——留使用者管理刀。）
- **FR-005**: 當某帳號有效單一會話時，登入 MUST 於**同一交易**內建立新會話、撤銷該帳號**其他所有**活躍
  會話（不誤傷當次新建會話）＋標記為他處登入撤銷＋落稽核（kicked）；被踢會話下次請求（換發或受保護
  存取）MUST 得 `7777`（他處登入、阻斷式提示）。並發登入以資料層唯一約束收斂為確定贏家。
- **FR-006**: 系統 MUST 於每個受保護請求前置**即時撤銷檢查**：查會話是否在撤銷集，命中則回對應碼
  （他處登入→`7777`／其餘撤銷→`8888`）；未命中＝放行。撤銷檢查以熱快取為快路徑、**連線故障退回權威
  資料源**（fail-closed、永遠正確、絕不因基建故障放行）；快取「無此紀錄」＝權威「未撤」＝放行。
- **FR-007**: 系統 MUST 新增登出端點 `POST /auth/logout`：以 **refresh 憑證身分**（非 access）驗證後撤銷
  該會話＋落稽核（logout）；access 憑證已過期時亦能登出撤銷（兌現「被擷取憑證登出後不可用」於過期邊界）。
- **FR-008**: 系統 MUST 提供通用**撤銷 primitive**「撤銷某使用者其他會話（保留指定會話）」，單元測試完備，
  供未來改密（B-029）／停用帳號／管理員踢除端點接線；本刀**不**建改密/停用/踢除端點（觸發遞延）。
- **FR-009**: 系統 MUST 實作**精確閒置逾時**：以伺服器端「最後活動時間」判定閒置（`now − 最後活動 > N`
  →換發拒 `8888`）；最後活動時間**僅由通過驗證的受保護請求**推進（含換發成功後重試的原請求），**換發
  端點本身絕不推進**（防背景 refresh-loop 繞過閒置）。設計相依前提：客戶端無背景/定時換發。
- **FR-010**: 憑證時效公式 MUST 為：access 時效＝`min(300 秒, N×30 秒)`（N＝`session_idle_timeout` 設定、
  換發時即時讀）；refresh 時效＝`N×60 + access 時效（+ 時鐘偏移餘裕）`（放寬以撐過精確界線）；此公式
  **supersede ADR 0030 的 `refresh 時效＝N×60`**——005 相關時效測試須連動改寫。
- **FR-011**: 閒置逾時／撤銷 MUST 走既有錯誤碼雙通道：他處登入踢除→`7777`（`auth.session.kicked`、
  阻斷式 modal 通道）；撤銷/閒置/停用→`8888`（`auth.session.reLogin`、靜默通道）；兩碼語意固定、**永不
  互換**（基建降級無原因可辨時 kicked 可降級為 `8888`，屬降級非語意互換）。閒置過期前端 MUST 顯示輕量
  「請重新登入」提示後重導（B-062、需新★軌道）。
- **FR-012**: 系統 MUST 建**最小會話稽核**：每一會話終止事件（kicked／revoked／logout／idle／reuse）落恰
  一列，含使用者、會話識別、事件型別、原因、時間、來源（best-effort、沿用 005 IP 取證最小版）。
- **FR-013**: 資料面 MUST 以單一新 migration 交付：①憑證表加**部分唯一約束**（每輪替鏈至多一枚有效憑證、
  作為競態/邏輯 bug 的 fail-loud 護欄）②新增最小會話稽核表；基線既有 seed／表凍結不動、down 對稱。
- **FR-014**: 系統 MUST 起手 Redis 基建（B-048）：以自動重連的連線管理器接入既有連線設定（`config.redis_url`
  已 fail-loud 載入、消費既有 documented-stub）；用途限撤銷集熱快取＋最後活動時間熱快取；**本刀不建
  發布/訂閱**（單/多實例皆以共享快取讀取即正確；跨實例本地快取失效通知留待真需求）。基建降級一律
  fail-closed 退權威源（FR-006/FR-009）。
- **FR-015**: 換發端點 MUST 對所有拒絕回 `8888`、**絕不回** `3333/9999/9998`（防前端自動換發死迴圈；
  沿用 005 精神、窄化措辭使他處登入 `7777` 可通過）；受保護存取無/失效身分→`3333`（fail-closed，沿用 004/005
  enforce_mw）。
- **FR-016**: 本刀 MUST **反轉 005 FR-016**（sys_token 零寫入）：憑證輪替落庫、005 的「零寫」回歸守門測試
  改寫為「輪替正確寫入」斷言（屬破紀律例外、經 ADR 0033 記錄）；13 碼矩陣零新碼（消費既有 `7777`、
  reuse `ModalLogout` 變體、`8888` `Logout`）。
- **FR-017**: base-web 改動 MUST 走 fork-delta 紀律＋新★軌道（ADR 0034 `BASE-WEB-LOGOUT-UX-WIRING`、
  兩用途）：(i) 主動登出改「先呼 `/auth/logout`（帶 refresh 憑證）再清本地」(ii) 攔截器靜默登出分支
  於登出前顯示輕量 toast（含 service 與 service-alova 兩同構副本）；皆帶 `原行:`＋fork-delta-lint；
  他處登入阻斷式 modal 分支既有、無需改。
- **FR-018**: 交付碼 MUST 承襲既有契約不破：憑證聲明欄形凍結（新增消費不改欄型）、簽章密鑰隔離
  （access／refresh 分離）、資料存取一律走 facade（handler 禁 path-root entity）、每新端點入路由註冊表
  ＋契約 case（覆蓋閘綠）；交付碼零前代 workspace 代號（§I.5）。
- **FR-019**: 本刀 MUST 於治理面落地（實作期）：以 ADR 0033 supersede ADR 0030（無狀態→DB-stateful）、
  以 ADR 0034 新增★軌道、將單一會話／輪替／即時撤銷三台狀態機的方向性不變式以 MINOR Amendment 入
  憲法 §I.7（島 A/B/C）、憲法 version 1.2.0→1.3.0；閒置島是否入 §I.7 於治理時最終確認。

### Key Entities *(include if feature involves data)*

- **會話（session）**：以會話識別（`sid`）為身分、跨輪替穩定；一會話＝一條輪替鏈；生命週期＝
  建立（登入）→輪替（續命）→終止（登出／踢除／盜用撤銷／閒置逾時）。
- **會話憑證（sys_token 列）**：一枚 refresh 憑證＝一列——擁有者、狀態（有效／已輪替／已撤銷）、憑證摘要
  （確定性、唯一）、所屬輪替鏈、發放/到期/使用時間；每鏈至多一枚有效（部分唯一約束）。
- **憑證對**：access（短時效、請求身分載體、無狀態）＋refresh（時效＝閒置窗＋、換發專用、落庫）。
- **單一會話政策**：全域 `single_session_default`（enum on/off 設定）＋每使用者 `session_policy`
  （inherit/single/multi、已備欄）；解析為「有效單一會話」。
- **撤銷集（denylist）**：被撤會話識別→原因（他處登入／撤銷）；熱快取為快路徑、權威資料源為真相。
- **最後活動時間**：每會話一筆熱快取時間戳；由受保護請求推進、換發不推進；精確閒置判定依據。
- **會話稽核（session_event）**：會話終止事件列——使用者、會話識別、事件型別、原因、時間、來源。
- **閒置逾時設定（session_idle_timeout）**：既有 number 設定鍵（分鐘、預設 60、範圍 5..=1440）；
  換發即時消費。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 持續使用者跨續命邊界 100% 憑證輪替透明、零中斷；呈遞已作廢舊 refresh 100% 判盜用撤整條會話、
  雙方登出；合法並發呈遞同一有效憑證 100% 不誤撤會話（寬限窗）。
- **SC-002**: 單一會話政策 on 時，同帳號新登入 100% 使其他會話下次請求得 `7777`（含被踢者 access 已過期
  走換發路徑亦得 `7777`、非 `8888`）；政策 off 時多會話 100% 並存不互踢；踢除 0% 誤傷當次新建會話。
- **SC-003**: 主動登出後，被擷取的 refresh 憑證 100% 無法再換發（`8888`）；access 憑證過期後登出 100% 仍能
  撤銷伺服器端會話；撤銷後受保護存取誤放行窗 ≤ 一個 access 時效。
- **SC-004**: 閒置逾時 100% 精確落在「最後真實活動＋N」（非提前）；背景 refresh-loop 100% 無法繞過閒置
  （閒置滿 N 仍 `8888`）；熱快取降級時 100% 不誤踢活躍者（界線偏寬、絕不提前）。
- **SC-005**: 撤銷檢查基建連線故障時 100% 退權威源、0% 因故障放行已撤會話（fail-closed）；`Ok(空)`（未撤）
  與連線故障 100% 嚴格分流。
- **SC-006**: 每一會話終止事件（kicked/revoked/logout/idle/reuse）100% 落恰一列稽核，可還原觸發原因與
  受影響會話。
- **SC-007**: 全部新端點 100% 有契約 case＋覆蓋閘綠；部分唯一約束對「同鏈二有效」100% fail-loud；憑證輪替
  抗撤銷穿插競態測試綠；`refresh_ttl_secs` 及 005 連動時效測試（含 `refresh_writes_zero_sys_token_rows`）
  100% 改寫並綠；13 碼零新碼；entity_access_lint／fork-delta-lint 全綠。
- **SC-008**: CDP 實機瀏覽器驗收全過（`CDP:127.0.0.1:9229`／Edge@9229、front-nginx 全鏈路；每項附 CDP
  可觀察證據〔L-053〕；toast 項前 restart base-web＋斷言頁面無 raw i18n key〔L-015〕）：
  **CDP-1** 切全域政策 on→A 登入→B 同帳號登入→A 彈阻斷 modal「已在他處登入」；
  **CDP-2** 設定調短→持續操作不登出→閒置滿 N 恰時登出＋「請重新登入」toast 後重導；
  **CDP-3** 正常換發連續不斷線＋舊憑證重放整條撤＋並發雙分頁不誤踢；
  **CDP-4** 登出後舊憑證換發失敗＋access 過期後登出仍撤。
- **SC-009**: Redis 起手可用（連線管理器自動重連）；憑證輪替落庫後憑證表無失控膨脹缺口（換發時清同鏈
  已過期作廢列＋膨脹治理列入 BACKLOG）。

## Assumptions

- 資料面沿用 baseline（seam 大半就位）：`sys_token` 表（9 欄＋5 索引）、`sys_user.session_id`＋
  `session_policy`（default `inherit`）、`system_settings` 已 seed `single_session_default`(off)＋
  `session_idle_timeout`(60)、憑證聲明含 `sid`/`jti`、`config.redis_url` 已 fail-loud 載入、`7777` 碼
  變體＋三映射齊備（零發出點）；本刀新增**一支 migration**（部分唯一約束＋會話稽核表）、無新設定列。
- 授權 seam 為接續契約（ADR 0027）：enforce_mw（身分注入、fail-closed `3333`）＋require_policy（即時角色
  →`5003`）沿用不重造；憑證簽章密鑰隔離既有。
- 會話語意 supersede ADR 0030（新 ADR 0033）：無狀態→DB-stateful 輪替 sliding refresh；承襲不變＝
  閒置為唯一登出條件、無絕對上限、設定變更下次續命生效、`8888`/`7777` 雙通道語意、使用者活性 gate。
- 破紀律例外（ADR 記錄）：反轉 005 FR-016（sys_token 零寫→輪替落庫）、放寬時效公式（動 ADR 0030 凍結
  常數）——皆立新 ADR supersede、改連動測試。
- Redis crate 版本**待 specify/plan 雙查 rev3 lockfile＋官方 stable、攤 user 選**（§6 版本紀律）；
  rust build/test 一律容器內、全程 serial（host 無 toolchain）。
- 新★軌道 `BASE-WEB-LOGOUT-UX-WIRING`（ADR 0034、兩用途）於 plan Constitution Check 觸發、走 §V.2
  MINOR Amendment；跨請求棧共用 refresh 在途承諾動到 service 層基建、其軌道歸屬於 plan 定。
- 本刀邊界（primitive 已備、觸發遞延）：改密（B-029）／admin 踢除／停用帳號撤銷之端點屬使用者管理刀；
  per-user `session_policy` 設定 UI 留使用者管理刀；節流（B-010）／IP 閘（B-019/B-024）為 auth family
  後兩把、複用本刀 Redis。
- 前端驗收面：base-web 無測試框架→靜態閘（build／typecheck／lint／locale 對等／契約對齊）＋CDP 實機
  走查；CDP 環境＝`127.0.0.1:9229`＋front-nginx。
- rev3 為唯讀受控參照（§I.5）：014（refresh 骨架含 rotation 段、005 已剝離）——結構參照、全新寫、
  禁整檔拷貝。
