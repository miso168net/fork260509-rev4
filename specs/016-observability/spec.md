## User Scenarios & Testing *(mandatory)*

### User Story 1 - 出事找得到人：告警規則＋通知投遞閉環 (Priority: P1)

維運者不再需要盯著畫面：系統把既有的安全與健康訊號（登入節流壓制、七源降級、IP 閘降級、授權面重載失敗、存取軌跡寫入故障、伺服端錯誤率、稽核表容量、回收 job 心跳）接上告警規則，條件成立即轉紅並**經 webhook 把通知真正送到維運者指定的接收端**。rev3 承襲基底只有「介面轉紅沒人看見」；本刀補上投遞＝告警閉環。

**Why this priority**: B-031 條目本體＋憲法四島告警義務（E1/F3/G1/J2）的消費端兌現；沒有投遞的告警等於沒發生——本刀核心價值。

**Independent Test**: 以測試手段觸發登入節流壓制→告警轉紅→本機 webhook 收器收到一則通知（內容含規則名與計數、不含任何原始 log 行）。

**Acceptance Scenarios**:

1. **Given** 觀測層啟用且投遞已設定，**When** 觸發登入節流壓制事件，**Then** 「壓制中」告警於評估窗內轉紅且 webhook 接收端收到通知。
2. **Given** 任一降級／故障訊號源（節流帳號維七源＋來源維五源、IP 閘降級、授權面重載重試／耗盡、存取軌跡寫入故障），**When** 該訊號出現，**Then** 對應告警規則可轉紅（四島義務全數有消費規則、零缺漏）。
3. **Given** 稽核四表任一表列數超過門檻，**When** 告警評估，**Then** 容量告警轉紅並投遞。
4. **Given** 回收 job 以真刪模式常駐，**When** 心跳距今超過兩倍執行間隔，**Then** 心跳超時告警轉紅；僅 dry-run 心跳存在而真刪心跳缺席時由**誤配偵測規則**轉紅（雙規則分工：超時規則於零序列時視為健康〔未部署不誤紅〕、誤配規則承載「僅 dry-run＝不健康」）。
5. **Given** 系統完全閒置（零請求零事件），**When** 告警評估，**Then** 全部規則維持綠燈（零 idle 誤報；伺服端錯誤率規則於無資料時顯式視為健康）。
6. **Given** 任一告警通知，**When** 檢視其內容，**Then** 僅含規則名、計數與時戳類資訊——不內嵌原始 log 行、不含個資。

### User Story 2 - 平時看得懂：log 可查可讀＋面板全景 (Priority: P2)

維運者開啟觀測層（平時預設不啟動），即可：①在面板上按欄位搜尋全容器 log（結構化單行事件、含請求追蹤識別碼），任一 API 請求可從 log 一路 join 到資料庫稽核列；②看到六片面板（總覽／後端服務／資料庫／快取／稽核軌跡／回收 job）與新增訊號格（攻擊廣度估計、撤銷名單命中、軟區負載、設定讀取頻次、稽核容量趨勢）；③每請求一行的完成事件 log（可依路徑過濾、預設全記）；④「拒因字典」面板——查到穩定訊息鍵（如 auth.login.failed）旁即顯正體中文對照，字典由前端語系檔機器生成、永不手維。

**Why this priority**: B-054／B-007／B-065／B-074／B-033殘（廣度估計）的兌現面；D4/D5/D6 落地載體。依賴底座但每格獨立可驗。

**Independent Test**: 啟用觀測 profile→發一個 API 請求→在 log 面板以其追蹤識別碼撈到完成事件與相關 log 行→再以同識別碼於稽核查詢對到同請求；開字典面板對照任一拒因鍵。

**Acceptance Scenarios**:

1. **Given** 觀測層啟用，**When** 發任一 API 請求，**Then** log 採集面出現該請求之結構化完成事件（含方法、路徑、狀態、耗時、追蹤識別碼），且以同識別碼可 join 到該請求之存取軌跡稽核列。
2. **Given** 路徑過濾清單設定為排除健康檢查路徑，**When** 健康檢查請求發生，**Then** 完成事件不輸出；清單清空後恢復全記（預設＝全記）。
3. **Given** 觀測層啟用，**When** 開啟六片面板，**Then** 全部 provision 成功且核心格有資料（機判：資料源查詢回非空）；資料庫面板於本部署形態下無恆空的篩選格。
4. **Given** 登入節流壓制事件已發生，**When** 檢視後端服務面板，**Then** 可見「本窗受壓制 distinct 帳號數／distinct 來源 IP 數」估計值兩格（誤差容許約 1%）。
5. **Given** 字典面板開啟，**When** 對照任一後端拒因鍵，**Then** 顯示正確之正體中文（含英文）對照；字典內容與前端語系檔重算比對零差異。
6. **Given** 撤銷名單命中／後備路徑、軟區路徑、設定讀取各發生一次，**When** 檢視面板，**Then** 對應計數格有非零讀數（服務重啟後計數序列仍存在、顯式為零而非空白）。

### User Story 3 - sys_token 自動回收：reaper 背景 job (Priority: P3)

維運者啟用回收 job（獨立 opt-in、預設不啟動）：以 dry-run 手動試跑可得候刪報告（零刪除）；常駐模式每日以真刪模式回收「有效期已過超過寬限期」的 token 列——未過期列（不分狀態）絕不刪；每輪完跑推送心跳與刪除量，失敗則不推心跳（由 US1 告警接手）。job 以專屬最小權限資料庫身分連線（僅能讀刪 token 表）。

**Why this priority**: B-063 兌現＋B-040（背景 job 最小權限憑證＝部署設計預設）首案；獨立於觀測面可測。

**Independent Test**: 造一批過期逾寬限期／過期未逾寬限期／未過期三類列→dry-run 回報候刪數且零刪→真刪後僅第一類消失→心跳與刪除量於面板可見。

**Acceptance Scenarios**:

1. **Given** token 表含「過期逾寬限期」「過期未逾寬限期」「未過期（各狀態）」三類列，**When** dry-run 執行，**Then** 僅第一類被列為候刪且資料庫零變動。
2. **Given** 同前置，**When** 真刪模式執行，**Then** 僅第一類被刪除；未過期列不分狀態全數保留（守恆）；撤銷判定、重放偵測、稽核語意零受損。
3. **Given** 常駐 sidecar 啟用，**When** 每輪完跑，**Then** 心跳時戳與刪除量更新且面板可見（真刪模式標記）；dry-run 試跑亦推心跳但帶獨立模式標記。
4. **Given** job 執行中途失敗（如資料庫不可達），**When** 該輪結束，**Then** 以非零狀態退出、輸出結構化錯誤事件、不推成功心跳。
5. **Given** job 之資料庫身分，**When** 嘗試逾越授權的操作（改寫 token 列、觸碰其他表），**Then** 一律被資料庫權限拒絕。

### User Story 4 - 開關自如、零業務影響：底座姿態與硬化 (Priority: P4)

開發者平時 `docker compose up` 得到與現況完全相同的六服務（零觀測容器、零額外資源）；觀測件全部 opt-in 分組啟用、全數設記憶體上限；log 採集容器以非 root 身分執行且不直接持有容器控制通道（經代理白名單、僅放行唯讀查詢，檔案系統讀取類端點一律拒絕）；觀測容器全滅時業務完全不受影響。

**Why this priority**: B-041（起手照配非 prod 補丁）＋「觀測層永遠是旁觀者」底線；獨立可驗。

**Independent Test**: 平時 up 比對容器清單與現況一致→啟用全部觀測 profile→kill 全部觀測容器→業務 API 請求成功率不變。

**Acceptance Scenarios**:

1. **Given** 未指定任何 profile，**When** `docker compose up`，**Then** 容器集合與本刀之前完全一致（六服務）。
2. **Given** 全部觀測 profile 啟用後，**When** 強制終止全部觀測容器，**Then** 業務 API 請求成功率不變且零 5xx 增量（機判）；延遲為觀察性記錄、不設容差判準（旁觀者驗證）。
3. **Given** log 採集容器運行中，**When** 檢視其執行身分與可達 API，**Then** 非 root 執行；容器控制通道僅經代理可達、代理拒絕檔案系統讀取／匯出／附加類端點（實測直打被拒）；代理走專用網段、業務網段內容器不可達之。
4. **Given** 追蹤識別碼標頭被注入控制字元或超長值，**When** 請求進入，**Then** 該值被棄用（淨化規則：白名單字元＋長度上限）、log 與稽核欄零污染。

### Edge Cases

- 觀測容器（含代理）任一或全部故障→業務零影響（旁觀者原則；重啟策略明定）。
- 快取服務故障→廣度估計寫入靜默失敗（best-effort、與既有壓制麵包屑同姿態）＋失敗計數可見；估計值偏低屬預期、不誤報告警（告警不綁廣度估計）。
- 伺服端錯誤率告警於零流量→顯式視為健康（無資料≠告警；防 idle 誤報）。
- 服務重啟→全部宣告的計數序列於首次抓取即存在（顯式為零）；推送閘道重啟→歷史心跳不失憶（持久卷）。
- 常駐 reaper 誤配為 dry-run→誤配偵測規則（dry-run 心跳存在且真刪心跳缺席）轉紅（堵「常駐空轉假健康」）。
- access token 有效期若未來調大至天級→寬限期前提（access 有效期遠小於 G）需重核（明文前提）。
- compose 專案名變更→log 採集比對與稽核面板查詢兩處寫死點需同步（施工錨定現名；偏離即零採集、面板全空）。
- webhook 接收端不可達→投遞失敗不影響告警規則狀態與業務；恢復後續投。
- 指標端點於 dev 為本機 loopback 可達（免認證）——與資料庫除錯埠同級、明文接受；不經反向代理對外（既有 404 擋塊）；prod 收攏歸部署刀。
- 字典來源語系檔新增／改鍵→機器重算即同步；手改生成物→守門檢查攔下。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 後端 log MUST 全環境輸出結構化單行事件（機器可解析、欄位級可查詢）；既有事件語意與訊息鍵 MUST 不變（純輸出形變更、wire 契約零觸碰）。
- **FR-002**: 每一 API 請求 MUST 於 log 事件攜帶請求追蹤識別碼（與存取軌跡稽核列同源）＝log↔稽核 join 鍵；識別碼 MUST 於單一入口點淨化（白名單字元＋長度上限、不合即棄用），下游 log 與稽核欄一體受惠。
- **FR-003**: 系統 MUST 輸出每請求一行的完成事件（方法、路徑、狀態、耗時、追蹤識別碼）；被 IP 閘擋下的請求亦記；MUST 提供路徑級過濾開關（預設空＝全記）；閘門判定序 MUST 不因此改變。
- **FR-004**: 系統 MUST 提供指標暴露端點：既有三個預留接點（信封例外、閘門豁免、反向代理擋塊）全數接上；全部宣告之計數序列 MUST 於服務啟動後首次抓取即存在（顯式為零）；並 MUST 建立 HTTP 請求級指標（請求數／延遲分布、含狀態碼維度）供錯誤率告警與流量面板使用。
- **FR-005**: 系統 MUST 新增下列觀測訊號：撤銷名單命中（含來源維度）與後備路徑計數、設定讀取頻次計數、軟區路徑命中計數、廣度估計操作失敗計數；稽核四表容量 MUST 以資料庫統計近似列數呈現（零全表掃描成本、不動後端程式）。
- **FR-006**: 登入節流壓制／鎖定事件發生時，系統 MUST 以 best-effort 寫入兩維（帳號、來源 IP）distinct 廣度估計（帶窗期時效；寫入失敗靜默＋失敗計數）；估計值 MUST 於指標端點可讀、面板呈現兩格；本刀告警規則 MUST NOT 依賴廣度估計。
- **FR-007**: 觀測容器 MUST 全數 opt-in 分組（log 採集組／指標組／背景 job 組）；未指定時 `docker compose up` 之容器集合 MUST 與本刀之前完全一致；觀測容器全滅 MUST 不影響業務請求；觀測容器 MUST 全數設記憶體上限。
- **FR-008**: log 採集組 MUST 提供：全容器 stdout 採集（有限保存期）、欄位級查詢介面；指標組 MUST 提供：時序庫（有限保存期）、資料庫與快取健康指標來源、推送閘道（含持久卷、重啟不失憶）；主機埠 MUST 依既有配號決策（43000／43100／49090／49091）。
- **FR-009**: 面板 MUST 全數 as-code provision（含資料源、告警規則、通知設定）：六片承襲面板（總覽／後端／資料庫／快取／稽核軌跡／回收 job）＋新增訊號格（廣度估計兩格、撤銷名單、軟區、設定讀取頻次、稽核容量趨勢）＋拒因字典面板；資料庫面板 MUST 於 docker 部署形態零恆空篩選格。
- **FR-010**: 告警規則 MUST as-code 落地且逐條綁通知投遞，至少涵蓋五組：①承襲 baseline 三條（伺服端錯誤率規則 MUST 於無資料／零流量時顯式視為健康）②節流「壓制中」（評估窗內任一壓制量級事件即轉紅）③降級／故障轉紅——MUST 全覆蓋四島義務訊號（節流降級全部標籤值〔帳號維七源＋來源維五源〕、IP 閘降級 log 事件、授權面重載重試／耗盡、存取軌跡寫入故障）④稽核容量超門檻（預設單表 1,000,000 列、可調）⑤回收 job 心跳雙規則（超時：超過兩倍執行間隔、零序列視為健康；誤配：僅 dry-run 心跳存在而真刪心跳缺席即轉紅；健康判定僅認真刪模式心跳、門檻與執行間隔同源）。
- **FR-011**: 告警通知 MUST 經 webhook 型接觸點投遞（單一通知策略全規則路由）；webhook URL MUST 走 secrets 管理、絕不明文進版本庫（含 provisioning 檔）；通知內容 MUST 不內嵌原始 log 行。
- **FR-012**: 回收 job MUST 為獨立 one-shot 程式：預設 dry-run（零刪除、輸出候刪報告）、顯式旗標才真刪；常駐 sidecar MUST 明文以真刪模式運行（每日一輪、間隔可調）；刪除判準 MUST 為「有效期（refresh）已過超過寬限期 G（預設 7 天、可調）」且未過期列不分狀態絕不刪；每輪完跑 MUST 推心跳（時戳＋刪除量、帶模式標記）、失敗 MUST 非零退出且不推成功心跳。
- **FR-013**: 回收 job MUST 以專屬最小權限資料庫身分連線（僅 token 表之讀取與刪除）；該憑證 MUST 走既有 secrets 慣例、密碼絕不進 migration、絕不進版本庫；job MUST 預留多 job 擴充位（job 名參數、預設 token 回收）。
- **FR-014**: 拒因字典 MUST 由工具自前端語系檔取 zh-TW 與 en-US 兩語機器生成（單一真相源；D9 拍板＝兩語對照）：對照表落機器生成參考區、面板檔落部署側 provisioning 樹（檔頭標示機器生成勿手改）；守門檢查 MUST 涵蓋「面板檔與語系檔重算零差異」；全鏈 MUST 零手維、後端零改動。
- **FR-015**: log 採集容器 MUST 非 root 執行且 MUST NOT 直接掛載容器控制通道：經專用代理存取、代理僅放行唯讀查詢端點且 MUST 拒絕檔案系統讀取／匯出／附加類端點（實測驗收）；代理 MUST 走專用網段、僅 log 採集容器可達。
- **FR-016**: 既有告警／麵包屑發送語意（四島義務＋量級麵包屑）MUST 零改動——本刀為消費端；施工中若需動發送語意 MUST 停手走憲法 Amendment 流程。
- **FR-017**: 指標標籤 MUST 預留 instance 維度設計（多副本前瞻、一句話留位）；計數序列顯式預註冊 MUST 成為本刀後之慣例（隨活書慣例表落地）。
- **FR-018**: 全部新增設定（路徑過濾清單、回收間隔、寬限期、記憶體上限、門檻值）MUST 有明文預設值且失讀時以預設運作（fail-default、不阻斷業務）。

### Key Entities *(include if feature involves data)*

- **告警規則組**: 五組 as-code 規則——訊號源、觸發條件、門檻、通知路由；與訊號清單一一對應可稽核。
- **通知接觸點**: webhook 型單一投遞目標——URL（secret）、通知策略（全規則路由）。
- **完成事件**: 每請求一行的結構化 log 事件——方法、路徑、狀態、耗時、追蹤識別碼；路徑過濾清單控制輸出範圍。
- **廣度估計對**: 帳號維＋來源 IP 維兩個帶時效的 distinct 估計值——壓制／鎖定事件寫入、指標端點讀出。
- **回收批次**: 一輪 reaper 執行——模式（dry-run／真刪）、候刪／實刪數、心跳時戳；判準＝有效期已過逾寬限期。
- **拒因字典**: 訊息鍵→正體中文／英文對照——自語系檔生成、雙產物（參考表＋面板）。

## Assumptions

- 發送側訊號已全數落地（007/008）：節流壓制麵包屑（量級、≤1/60s/key）、降級結構化告警（帳號維七源＋來源維五源）、IP 閘 per-cidr 阻擋與降級事件、授權面重載計數——本刀純消費、零發送語意改動（憲法四島義務 E1/F3/G1/J2＋島 E3 麵包屑明文）。

### 設計取捨（有意識接受）

- dev 下指標端點本機 loopback 可達（免認證）——與資料庫除錯埠同級；prod 收攏歸部署刀。
- 廣度估計誤差約 1%＋快取故障時估計值偏低（失敗計數可見）——forensic 增益定位、告警不依賴。
- 稽核容量用資料庫統計近似列數（非精確計數）——容量告警用途足夠、零掃描成本。
- 完成事件預設全記（含健康檢查與抓取請求）——join 完整性優先、噪音由保存期界定；過濾開關留給噪音實際成為問題時。
- 觀測容器記憶體上限量級值施工期實測調（設上限本身為硬要求、防 dev 機資源事故）。
- 容量門檻預設 1,000,000 列與壓制告警評估窗屬工程預設——規則內可調、審 spec 可翻案。
