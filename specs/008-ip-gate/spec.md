## User Scenarios & Testing *(mandatory)*

### User Story 1 - 系統能誠實還原並標記請求的真實來源位址 (Priority: P1)

系統在每個進入的請求上，從傳輸層對端位址與轉發標頭鏈中推導出「這個請求真正來自哪個位址」，並同時標記「這個判斷有多可信」。當請求方直接連線時，其傳輸層來源無法偽造，系統據此取得高信心的位址；當請求經過受信任的代理層（CDN、反向代理、通道）時，系統依部署方顯式宣告的信任拓樸逐層剝除，取回最終訪客位址；當任何一環無法確認時，系統誠實地標記為低信心，而非假裝知道。

此後所有以「來源位址」為鍵的機制（存取控制、節流、稽核鑑識）都只消費這個結果。

**Why this priority**: 這是整把刀的地基。per-IP 的一切安全性 100% 建立在「這個位址無法被請求方偽造」之上；沒有它，後續的閘門與節流都可以被任意轉發標頭繞過。它本身也已交付價值——稽核列的來源位址與信心標記從「恆為反向代理自己、信心恆為低」變成真值，鑑識能力從零變成可用。

**Independent Test**: 不需要任何閘門或節流即可完整驗證——構造四種 ingress 拓樸的請求（直連／CDN 前置／通道直連／負載平衡多副本），檢查稽核列落下的來源位址與信心值是否符合預期；並以偽造的轉發標頭嘗試冒充任意來源，驗證系統不採信。

**Acceptance Scenarios**:

1. **Given** 請求方直接連線且其位址不在任何信任集內，**When** 該請求攜帶偽造的轉發標頭（宣稱來自別的位址），**Then** 系統採用傳輸層對端位址為真實來源、完全忽略該標頭，信心標記為「直連」。
2. **Given** 部署宣告了 CDN 網段，**When** 請求的轉發鏈中出現 CDN 網段，**Then** 系統以最右側的 CDN 段為錨、取其左鄰第一個非 CDN 位址為真實來源，並剝除該錨右側的一切內容（不論那裡是什麼）。
3. **Given** 無 CDN 段、轉發鏈右側數跳皆屬宣告的信任段，**When** 系統解析該鏈，**Then** 由右往左跳過所有信任段，第一個非信任段的位址即真實來源，信心標記為「代理鏈潔淨」。
4. **Given** 轉發鏈全部落在信任段內（無可取的訪客位址），**When** 系統解析該鏈，**Then** 回退為傳輸層對端位址，信心標記為「回退」。
5. **Given** 請求經由宣告的通道來源進入且解析結果為「回退」，**When** 該通道來源提供了訪客位址標頭，**Then** 系統採信該標頭作為真實來源，但信心維持「回退」（不因未經位置交叉驗證的來源而升等）。
6. **Given** 某內網主機屬於信任段但**不屬於**通道來源集，**When** 它偽造通道的訪客位址標頭，**Then** 系統不採信該標頭。
7. **Given** 部署宣告了「掛載 CDN 驗證閘的我方反向代理出口」，**When** 請求由該出口進入且攜帶驗證閘產生的驗證標記、且標頭中的訪客位址與還原結果一致，**Then** 信心升為最高等級；若不一致則降為「異常」等級並留痕；**且真實來源位址在兩種情況下都不改變**。
8. **Given** 請求方直接自行攜帶偽造的「CDN 驗證標記」，且其傳輸層對端**不屬於**驗證閘出口集，**When** 系統解析，**Then** 該標記不被採信、信心不得升等。
9. **Given** 轉發標頭含超量 token、附帶連接埠／區域識別／方括號包裹、或無法解析的垃圾內容，**When** 系統正規化該鏈，**Then** 超過上限的部分被截斷、格式修飾被剝除、垃圾 token 被丟棄，且解析不 panic、不拒絕請求。
10. **Given** 信任模型設定檔缺失、整體無法解析、或某集合含有無效網段字面，**When** 系統啟動，**Then** 受影響的集合退化為空集（設定整體壞掉則全空＝一切視為直連），系統正常啟動、發出結構化告警，且**不擴大**任何信任範圍。

### User Story 2 - 維運者能以位址規則封鎖或放行來源 (Priority: P2)

超級管理員維護一份來源位址規則清單（放行規則與阻擋規則），系統對每一個進入的請求以其真實來源位址比對：命中放行規則即放行（即使同時命中阻擋規則）；命中阻擋規則即拒絕；兩者皆未命中則放行。規則變更後短時間內於所有服務副本生效。

**Why this priority**: 這是本刀對維運者最直接的價值——面對正在攻擊的來源可以立即封鎖，面對已知的合作夥伴或辦公室出口可以豁免。它依賴 US1 的真實位址，但不依賴節流。

**Independent Test**: 建立一條阻擋規則涵蓋某個測試來源，驗證該來源的請求被拒絕；再建立一條放行規則涵蓋同一來源，驗證改為放行（白優先）；刪除後恢復預設放行。

**Acceptance Scenarios**:

1. **Given** 無任何規則，**When** 任意來源發出請求，**Then** 請求被放行（預設放行）。
2. **Given** 存在一條涵蓋來源 X 的阻擋規則，**When** 來源 X 發出請求，**Then** 請求被拒絕，回應使用既有的「禁止存取」業務碼（不新增錯誤碼）。
3. **Given** 來源 X 同時被一條放行規則與一條阻擋規則涵蓋，**When** 來源 X 發出請求，**Then** 請求被放行（放行優先於阻擋，且與規則的建立順序、排序欄位無關）。
4. **Given** 服務健康檢查端點與觀測端點，**When** 任何來源存取它們，**Then** 一律放行（不受規則影響）。
5. **Given** 還原後的真實來源位址落在迴環或私有網段內，**When** 系統判定，**Then** 一律放行（結構性豁免，僅豁免「阻擋」，不豁免節流）。
6. **Given** 規則清單中存在一條類型欄位為未知值的規則，**When** 系統載入規則集，**Then** 該規則被跳過、其餘規則正常生效、不影響啟動。
7. **Given** 超級管理員新增一條規則，**When** 寫入成功，**Then** 該規則在 5 秒內於所有服務副本上生效。
8. **Given** 系統啟動時無法讀取規則資料，**When** 服務啟動完成，**Then** 規則集為空、一切請求放行（不因基建故障而拒絕本應放行的請求），並發出告警。
9. **Given** 服務執行中收到規則變更通知但重新讀取失敗，**When** 系統處理該次失敗，**Then** **保留上一份已知良好的規則集**（不清空）、發出告警並退避重試。
10. **Given** 某來源被阻擋，**When** 該來源在短時間內重複請求，**Then** 系統記錄阻擋量級訊號（以規則網段為維度、含壓制），且**不得**將來源位址本身寫入觀測標籤。

### User Story 3 - 維運者不會把自己鎖在門外 (Priority: P3)

超級管理員對規則做任何寫入操作（新增、修改、刪除、復原）之前，系統先模擬「這次變更之後的規則集」，如果那會使操作者當下的來源位址被阻擋，系統拒絕這次寫入並明確告知原因。

**Why this priority**: 這是 IP 閘門唯一的「拒絕寫入」保護，也是它可以被放心啟用的前提。缺了它，一次手滑就會讓維運者失去所有管理入口。獨立於節流，可單獨驗證。

**Independent Test**: 以操作者當下的來源位址為標的，分別嘗試四種等效自鎖路徑，驗證四種都被拒絕；再驗證針對其他位址的相同操作都能成功。

**Acceptance Scenarios**:

1. **Given** 操作者當下來源為 X，**When** 新增一條涵蓋 X 的阻擋規則，**Then** 寫入被拒絕、回傳自鎖錯誤。
2. **Given** 操作者當下來源為 X 且有一條阻擋規則涵蓋 X、另有一條放行規則涵蓋 X（放行使其仍可通行），**When** 刪除該放行規則，**Then** 寫入被拒絕（變更後 X 將被阻擋）。
3. **Given** 存在一條被軟刪除的、涵蓋 X 的阻擋規則，**When** 復原該規則，**Then** 寫入被拒絕。
4. **Given** 操作者當下來源為 X，**When** 修改某條規則使其變更後涵蓋並阻擋 X，**Then** 寫入被拒絕。
5. **Given** 操作者當下來源為 X，**When** 新增涵蓋 X 的**放行**規則，**Then** 寫入成功（放行永不造成自鎖）。
6. **Given** 操作者經由不同出口（例如遠端連線）操作，**When** 對其辦公室出口建立阻擋規則，**Then** 寫入成功（自鎖檢查只保護操作者當下的連線出口——此侷限為明文取捨，見「假設」節）。
7. **Given** 規則資料已存在一條相同網段與類型的有效規則，**When** 新增重複規則，**Then** 回傳業務衝突碼（不是伺服器錯誤）。
8. **Given** 任何規則寫入，**When** 寫入成功，**Then** 對應的操作稽核紀錄與規則變更在同一交易中落地。

### User Story 4 - 系統能阻止來自單一來源的輪換帳號名攻擊 (Priority: P4)

系統對每一個真實來源位址獨立計算「滑動時窗內的登入失敗次數」。超過軟門檻後，該來源的所有登入都必須通過圖形驗證；超過硬門檻後，該來源的登入被鎖定直到時窗滑過。**關鍵語意：某個帳號在該來源上成功登入，不會重置該來源的失敗計數。**

**Why this priority**: 這正是本刀立刀的理由。007 的帳號級節流以「所送出的帳號名」為鍵，攻擊者每發換一個帳號名就落入全新的計數桶、永不觸鎖；聚合維度的防護只能由來源位址承擔。它依賴 US1（真實位址）與 US2（放行規則供白名單跳節流），故排在其後。

**Independent Test**: 以兩個模擬來源各自打失敗登入，驗證計數互相隔離；對單一來源持續打失敗登入，驗證依序進入軟區與硬鎖；並在失敗序列中穿插一次成功登入，驗證計數**不被重置**。

**Acceptance Scenarios**:

1. **Given** 來源 X 在時窗內的登入失敗次數達到軟門檻，**When** 該來源上任一帳號（包含從未失敗過的帳號）嘗試登入，**Then** 系統要求提供圖形驗證碼；驗證碼題目仍綁定所送出的帳號名、提交即消耗。
2. **Given** 來源 X 在時窗內的登入失敗次數達到硬門檻，**When** 該來源嘗試登入，**Then** 系統拒絕，回應使用既有的一般化業務碼與靜態訊息，**不揭露**觸發的是來源維度還是帳號維度、不揭露剩餘時間、不揭露帳號是否存在。
3. **Given** 來源 X 已累積 N 次失敗（N 小於硬門檻），**When** 某個持有有效憑證的帳號自 X 成功登入，**Then** X 的失敗計數**不歸零**——後續失敗繼續累積，硬門檻仍會如期觸發。
4. **Given** 帳號維度已硬鎖、來源維度僅在軟區，**When** 該帳號自該來源登入，**Then** 判定為硬鎖（任一維度硬鎖即硬鎖）。
5. **Given** 帳號維度在軟區、來源維度亦在軟區，**When** 登入，**Then** 判定為軟區（要求驗證碼）。
6. **Given** 兩個不同來源各自累積失敗，**When** 其中一個達到硬門檻，**Then** 另一個不受影響（維度隔離）。
7. **Given** 來源 X 被硬鎖，**When** 超級管理員對該來源執行手動解鎖，**Then** X 的鎖定解除、後續登入恢復正常。
8. **Given** 三個門檻設定（硬門檻、時窗長度、軟門檻）之任一者被調整，**When** 下一次登入判定發生，**Then** 使用調整後的值（無需重啟）。
9. **Given** 計數資料源或快取層故障，**When** 登入判定發生，**Then** 系統偏向放行（不因基建故障拒絕本應放行的登入）並發出結構化告警。
10. **Given** 因來源維度而觸發的鎖定或驗證碼要求，**When** 該次嘗試未經密碼實際驗證即被短路，**Then** **不落**登入稽核列（量級訊號走觀測層）。

### User Story 5 - 已知的可信來源不受節流干擾 (Priority: P5)

被顯式登記為放行規則的來源（例如公司辦公室出口、合作夥伴閘道），其登入請求完全跳過來源維度的節流判定。

**Why this priority**: 這是 NAT 共用出口誤傷的主要緩解手段，也是「第三方惡意觸鎖」的徹底解法之一。它依賴 US2（規則）與 US4（節流），故排最後。

**Independent Test**: 為某測試來源建立放行規則，令其失敗次數遠超硬門檻，驗證其登入仍不被來源維度鎖定；移除規則後恢復受限。

**Acceptance Scenarios**:

1. **Given** 來源 X 命中放行規則，**When** X 的失敗次數超過硬門檻，**Then** X 的登入不因來源維度被鎖定或要求驗證碼（帳號維度的節流仍照常生效）。
2. **Given** 來源 Y 位於結構性豁免的私有網段但**未**登記放行規則，**When** Y 的失敗次數超過硬門檻，**Then** Y 仍被來源維度鎖定（結構性豁免只豁免「阻擋」、不豁免節流）。
3. **Given** 規則集因基建故障退化為空集，**When** 原本命中放行規則的來源發出登入，**Then** 該來源退回一般節流（放行規則失效的後果為明文取捨，見「假設」節）。

### User Story 6 - 稽核與鑑識能力（來源位址、信心值、地理區域） (Priority: P6)

登入嘗試、操作紀錄與會話事件三類稽核資料，其來源位址欄記錄還原後的真實位址、信心欄記錄七等級真值；登入嘗試另以盡力而為方式標記地理區域。

**Why this priority**: 鑑識價值高但不阻擋任何安全機制；且部分能力（信心值、真實位址）已隨 US1 自然交付，此故事聚焦地理區域與跨表一致性。

**Independent Test**: 以已知地理歸屬的模擬位址發出登入，檢查稽核列的來源位址、信心值、地理區域三欄；移除地理資料檔後重啟，驗證服務正常啟動、地理欄留空、登入不受影響。

**Acceptance Scenarios**:

1. **Given** 一次登入嘗試，**When** 系統落下稽核列，**Then** 來源位址欄為還原後真實位址、對端位址欄維持傳輸層對端、信心欄為七等級之一。
2. **Given** 地理資料檔存在且可用，**When** 一次登入嘗試落列，**Then** 地理區域欄以盡力而為方式填入。
3. **Given** 地理資料檔缺失或損壞，**When** 服務啟動，**Then** 服務正常啟動（不崩潰）、地理功能停用、地理區域欄留空、登入流程完全不受影響。
4. **Given** 一次會話事件（換發、撤銷、閒置登出）或一次管理操作，**When** 系統落下對應紀錄，**Then** 其來源位址／信心欄同樣採用還原後的真值。

### User Story 7 - 憑證換發與登出端點不再裸奔 (Priority: P7)

憑證換發與登出兩個公開端點納入既有的網路層速率限制，超量請求在抵達應用層之前即被拒絕。

**Why this priority**: 補上 007 明文列為邊界外的缺口（兩端點皆帶資料庫寫入路徑、暴力灌打僅受一般容量約束）。實作成本最低、與其餘故事無耦合。

**Independent Test**: 對兩端點分別以超過速率上限的頻率發送請求，驗證回應為網路層拒絕語意。

**Acceptance Scenarios**:

1. **Given** 對憑證換發端點以超過速率上限的頻率發送請求，**When** 超出突發容量，**Then** 請求在抵達應用層前被拒絕，回應為網路層拒絕（非業務信封）。
2. **Given** 登出端點同上，**When** 超出突發容量，**Then** 同樣被網路層拒絕。
3. **Given** 正常使用者的操作節奏（含滑動式憑證換發），**When** 使用系統，**Then** 永不觸發此限制。

### Edge Cases

- **偽造轉發標頭**：不受信的直連請求方攜帶任意轉發標頭 → 標頭整條忽略（US1-1）。
- **轉發標頭洪泛**：token 數超過上限 → 截斷處理，不放大解析成本。
- **畸形位址 token**：含連接埠、IPv6 區域識別、方括號、純垃圾 → 剝除或丟棄，解析不失敗。
- **通道來源非迴環位址**：通道來源位於獨立主機（非迴環／私網）時，其位址必須同時被跳過集涵蓋，否則還原結果會塌縮為該通道來源常數、且訪客位址標頭永不被採信 ⇒ 信任集與跳過集**必須同源對稱**。
- **請求方自帶「CDN 驗證標記」**：在無我方反向代理可剝除標頭的拓樸（負載平衡直連）下，若不加來源限制，可將信心騙升至最高等級 ⇒ 驗證標記僅在傳輸層對端屬於「驗證閘出口集」時才採信，且反向代理層必須無條件覆寫／剝除請求方送入的同名標頭。
- **CDN 網段清單過期**：真實 CDN 流量的信心降為次高等級（不誤放行、fail-safe 方向）。
- **信任模型設定壞掉**：全空模型＝一切視為直連 ⇒ 經反向代理進入的請求，其來源位址將被鍵到反向代理本身，來源維度的防護實質失效 ⇒ **告警必發**（同「假設」節的部署前提證偽後果）。
- **規則資料讀取失敗**：啟動時失敗 → 空規則集（無舊值可留）；執行中重新讀取失敗 → **保留上一份已知良好規則集**（清空會同時抹掉阻擋規則與放行規則，一次瞬時故障即造成無界時長的降級與放行名單失效放大）。
- **無請求上下文**（例如以最小化方式直呼應用層、單元測試路徑）：閘門放行、來源維度節流跳過（帳號維度仍生效）；上下文缺席**絕不**升級為伺服器錯誤。
- **還原後位址落入私有網段**：結構性豁免放行（僅豁免阻擋），但仍受來源維度節流約束。
- **過寬的放行規則**：一條涵蓋大網段的放行規則同時使該範圍免疫全部阻擋規則、並完全跳過來源維度節流 ⇒ 單點繞過風險（見「假設」節）。
- **共用出口內部的攻擊者**：位於同一 NAT 出口內的攻擊者可持續打滿硬門檻，使整個出口的所有使用者被鎖；四層緩解對此無效（見「假設」節）。
- **維運者與被鎖出口同源**：出口被鎖時，位於該出口的超級管理員本人亦被鎖（回應一般化、不揭露維度），需自替代出口操作解鎖。
- **帳號維度與來源維度同時觸發**：四種組合（軟×軟、軟×硬、硬×軟、硬×硬）的判定必須被唯一決定——任一硬鎖即硬鎖；否則任一軟區即軟區；否則放行。
- **手動解鎖的維度**：解鎖操作需能指明針對帳號維度或來源維度（既有端點的請求形擴充，見「治理與相依」節）。
- **地理資料檔缺失**：啟動守門，不得因此崩潰。

## Requirements *(mandatory)*

### Functional Requirements

#### 信任錨——真實來源位址還原（US1）

- **FR-001**: 系統 MUST 對每一個進入的請求推導出「真實來源位址」與「信心等級」二元組，並 MUST 以**單一權威判定函式**產出（政策與判定不得存在第二份實作；判定結果 MUST 同時回傳命中依據，供觀測層消費）。
- **FR-002**（peer-gate）: 當傳輸層對端位址**不屬於**信任集時，系統 MUST 直接採用該對端位址為真實來源，且 MUST 完全忽略請求所攜帶的任何轉發標頭；信心＝「直連」。
- **FR-003**（Tier-1 位置錨）: 當轉發鏈中存在已宣告的 CDN 網段時，系統 MUST 以**最右側**的 CDN 段為錨，取其左鄰第一個非 CDN 位址為真實來源，並 MUST 剝除該錨右側的全部內容；信心＝「CDN 錨定」。若錨左側無非 CDN 位址，則回退（FR-005）。
- **FR-004**（Tier-2 最右不可信）: 當轉發鏈中無 CDN 段時，系統 MUST 由右往左逐點跳過屬於跳過集的位址，第一個不屬於跳過集者即真實來源。★**信任集與跳過集 MUST 自同一來源導出、內容對稱**（含通道來源集與驗證閘出口集）。當路徑經過被標記為「雙重身分」的我方出口、或相鄰綁定驗證不符時，信心降為「代理鏈軟性」；否則為「代理鏈潔淨」。
- **FR-005**（回退）: 當轉發鏈全部落於跳過集內、或無可取的位址時，系統 MUST 回退為傳輸層對端位址，信心＝「回退」。
- **FR-006**（正規化）: 系統 MUST 對轉發標頭做正規化後才解析：token 數上限固定、每個 token MUST 剝除連接埠／IPv6 區域識別／方括號包裹、無法解析者 MUST 丟棄。正規化 MUST NOT 因畸形輸入而失敗或拒絕請求。
- **FR-007**（通道覆蓋層）: 當基礎解析結果為「回退」**且**傳輸層對端屬於通道來源集時，系統 MUST 採信通道提供的訪客位址標頭作為真實來源，且信心 MUST 維持「回退」（不因未經位置交叉驗證的來源升等）。傳輸層對端屬於信任集但**不屬於**通道來源集者，其攜帶的同名標頭 MUST NOT 被採信。
- **FR-008**（CDN 驗證覆蓋層）: 系統 MUST 僅在傳輸層對端屬於**驗證閘出口集**、且反向代理注入的驗證標記為真、且訪客位址標頭有值、且基礎信心屬於可升等集合時，才比對兩者：一致則升為最高信心；不一致則降為「異常」信心並留痕。此覆蓋層 MUST NOT 改變真實來源位址；對「回退」信心 MUST 為無作用。
- **FR-009**（信心值域）: 信心等級 MUST 為固定的七個等級，並以穩定的小寫識別字寫入稽核欄。
- **FR-010**（信任模型設定）: 信任拓樸 MUST 由部署方以設定檔顯式宣告、於服務啟動時一次載入（非執行期熱讀）。所有集合的預設值 MUST 為空集；任一集合含無效網段字面時，該集合 MUST 整個清空；設定整體無法解析時 MUST 退化為全空模型（一切視為直連）。系統 MUST NOT 提供任何隱含的寬鬆預設值。
- **FR-011**: 信任模型設定缺失、部分清空或整體退化時，系統 MUST 發出結構化告警並正常啟動。

#### IP 存取控制閘（US2）

- **FR-012**（判定序）: 對每個請求，系統 MUST 依下列固定順序判定：①健康檢查與觀測端點一律放行 → ②請求上下文缺席時放行 → ③真實來源位址落於結構性豁免網段時放行 → ④命中任一放行規則時放行 → ⑤命中任一阻擋規則時拒絕 → ⑥其餘放行。
- **FR-013**（集合語意）: 規則比對 MUST 為集合任一命中（any-match），**MUST NOT** 為順序化的規則鏈；排序欄位僅供清單顯示，MUST NOT 參與判定。
- **FR-014**（阻擋回應）: 阻擋 MUST 重用既有的「禁止存取」業務碼與其既有的 HTTP 狀態對應，**MUST NOT** 新增錯誤碼。
- **FR-015**（結構性豁免射程）: 結構性豁免 MUST 僅豁免「阻擋」，MUST NOT 豁免來源維度節流。
- **FR-016**（真相與判定面）: 規則資料 MUST 以持久化儲存為唯一真相；每請求判定 MUST 讀取記憶體中的規則集副本、MUST NOT 觸發任何每請求的資料庫或快取查詢。
- **FR-017**（收斂）: 規則寫入後 MUST 通知其他服務副本重新載入；副本 MUST 在 5 秒內收斂至新規則集。
- **FR-018**（fail-OPEN 全鏈）: 規則載入失敗、通知機制不可用、觀測寫入失敗，皆 MUST 偏向放行且發出結構化告警。★**啟動初載失敗** → 空規則集；★**執行中重新載入失敗** → **MUST 保留上一份已知良好的規則集**（不得清空）、告警並退避重試。
- **FR-019**（未知規則類型）: 載入規則集時遇到類型欄位為未知值者 MUST 跳過該列並繼續，MUST NOT 使載入失敗。
- **FR-020**（阻擋量級觀測）: 系統 MUST 記錄被阻擋請求的量級訊號（以命中的規則網段為維度、含發送壓制）；★來源位址本身 MUST NOT 進入觀測標籤（高基數禁令）。

#### 規則寫端與自鎖防護（US3）

- **FR-021**（端點集合）: 系統 MUST 提供規則的查詢、新增、修改、刪除（軟刪）、復原能力，其授權 MUST 走既有的政策機制。
- **FR-022**（自鎖防護）: 對新增／修改／刪除／復原四種寫入操作，系統 MUST 先建構「變更之後的規則集」，並以與請求判定完全相同的判定函式檢驗操作者當下的真實來源位址；若判定為「阻擋」則 MUST 拒絕該次寫入並回傳自鎖錯誤。★此為本刀**唯一的 fail-closed 例外**。
- **FR-023**（輸入守門）: 網段字面 MUST 正規化後儲存；規則類型 MUST 限於放行／阻擋二值。有效規則的「網段×類型」MUST 唯一；重複寫入 MUST 回傳業務衝突碼（MUST NOT 為伺服器錯誤）。
- **FR-024**（稽核原子性）: 規則變更與其操作稽核紀錄 MUST 於同一交易中落地。
- **FR-025**（寫後生效）: 寫入成功後 MUST 立即更新本副本的判定面並廣播變更通知。

#### per-IP 節流（US4、US5）

- **FR-026**（計數維度）: 系統 MUST 以真實來源位址為鍵，獨立計算滑動時窗內的登入失敗次數。
- **FR-027**（★計數下界語意）: 來源維度的時窗下界 MUST 只取兩個來源——**時窗起點**與**該來源的手動解鎖標記**。★**MUST NOT** 納入「時窗內最近一次成功登入」作為下界（該語意在帳號維度成立、在來源維度反轉為破口：持有任一有效憑證者可藉穿插成功登入無限重置該來源的失敗計數，使硬門檻永不觸發，恰好繞過本刀所針對的輪換帳號名攻擊）。此不變式 MUST 由負向自證測試守門。
- **FR-028**（兩段式）: 來源維度失敗數超過軟門檻 → 該來源的所有登入 MUST 要求圖形驗證；超過硬門檻 → 該來源的登入 MUST 被拒絕至時窗滑過。兩者的回應 MUST 使用既有的一般化業務碼與靜態訊息，MUST NOT 揭露觸發維度、剩餘時間或帳號存在性。
- **FR-029**（跨維度合成）: 帳號維度與來源維度 MUST 並列判定，合成規則為：任一維度硬鎖 → 硬鎖；否則任一維度軟區 → 軟區；否則放行。★驗證碼題目 MUST 仍綁定所送出的帳號名、提交即消耗（既有不變式不變）。
- **FR-030**（帳號維度不受污染）: 帳號維度的判定鍵 MUST 維持為所送出的帳號名原文，MUST NOT 因本刀而摻入來源位址。（釐清：既有「判定不得依賴來源 IP」之條文，其射程為**帳號維度的判定鍵**；本刀新增的是獨立並列的來源維度，兩者不衝突。）
- **FR-031**（門檻設定）: 來源維度 MUST 有三個獨立於帳號維度的設定鍵（硬門檻／時窗長度／軟門檻），MUST 可於執行期調整並即時生效，且 MUST 有值域約束。
- **FR-032**（放行跳節流）: 命中**顯式放行規則**的來源，其登入 MUST 完全跳過來源維度的節流判定（含其快取層）。★MUST 只認顯式放行規則；結構性豁免網段 MUST NOT 跳節流。
- **FR-033**（手動解鎖）: 既有的手動解鎖能力 MUST 能指明作用於帳號維度或來源維度。
- **FR-034**（快取層與降級）: 來源維度的快取層 MUST 沿用既有的負快取不變式（僅短路已鎖判定、僅由再判路徑寫入、存活時間不長於時窗、命中不續期）。任一資料源或快取故障 MUST 偏向放行並發出結構化告警。
- **FR-035**（稽核邊界）: 因來源維度而被短路的嘗試（鎖定拒絕、驗證碼要求）MUST NOT 落登入稽核列；量級訊號走觀測層。

#### 稽核與鑑識（US6）

- **FR-036**: 登入嘗試稽核的來源位址欄 MUST 記錄還原後的真實位址；對端位址欄 MUST 維持傳輸層對端；信心欄 MUST 記錄七等級真值。★此為**欄位語意升級、非結構變更**。
- **FR-037**: 操作稽核與會話事件的來源位址／信心欄 MUST 同步採用還原後的真值。
- **FR-038**（地理標記）: 登入嘗試 MUST 以盡力而為方式標記地理區域。地理資料不可用時，系統 MUST 正常啟動、該欄留空、且 MUST NOT 影響登入流程或使服務崩潰。

#### 網路層速率限制（US7）

- **FR-039**: 憑證換發端點與登出端點 MUST 納入既有的網路層速率限制區；觸發時 MUST 於抵達應用層前被拒絕、回應為網路層拒絕語意（非業務信封）。突發容量 MUST 足以容納正常使用者的操作節奏。
- **FR-040**: 既有登入端點與取題端點的速率限制區、其鍵、速率與拒絕語意 MUST NOT 被本刀改動。

#### 開發環境拓樸前置（施工分段 P0）

- **FR-041**: 開發環境的前端 API 請求 MUST 以同源相對前綴發出，並 MUST 與正式環境的請求路徑同形（單跳、轉發鏈一元素）；正式建置產物 MUST 能連通後端。★此前置使本刀的實機驗收與正式環境等價。

#### 本刀邊界（MUST NOT）

- **FR-042**: 本刀 MUST NOT 交付規則管理的前端頁面（API-only；既有選單項續留未建頁狀態）。
- **FR-043**: 本刀 MUST NOT 將被阻擋的請求寫入存取日誌資料表（量級訊號只走觀測層）。
- **FR-044**: 本刀 MUST NOT 引入順序化規則鏈或優先權判定欄。
- **FR-045**: 本刀 MUST NOT 交付來源廣度估計、觀測儀表板告警規則（歸觀測層刀）；MUST NOT 交付放行規則的分型（「僅跳節流」／「僅提高門檻」）。
- **FR-046**: 本刀 MUST NOT 新增任何錯誤碼。

### Key Entities

- **來源位址規則**：一條規則描述「某個網段」被「放行」或「阻擋」，附帶備註與排序欄（僅供顯示）。有效規則以「網段×類型」唯一。支援軟刪除與復原。**其資料結構已存在於凍結基線，本刀不新增或變更結構。**
- **信任模型設定**：部署方宣告的信任拓樸，包含內部預設段、通道來源集、驗證閘出口集、CDN 段（含其訪客位址標頭名）、我方公開出口（可標記雙重身分）、公開出口與其後置內網的綁定關係。全部預設為空。
- **請求上下文**：每個請求解析一次的結果，含真實來源位址、傳輸層對端位址、信心等級、原始轉發標頭、地理區域、追蹤識別。供閘門、節流、稽核共同消費。
- **登入嘗試稽核**：既有的僅追加紀錄；本刀升級其來源位址、信心、地理三欄的**值語意**，不動其結構。
- **來源維度門檻設定**：三個可於執行期調整的設定鍵（硬門檻／時窗長度／軟門檻），與帳號維度的三鍵獨立。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在四種進入拓樸（直連／CDN 前置／通道直連／負載平衡）的完整案例表下，真實來源位址與信心等級的還原結果 100% 符合預期。
- **SC-002**: 不受信的請求方無論攜帶何種轉發標頭或驗證標記，皆 100% 無法使系統採信其宣稱的來源位址、亦無法使信心等級升等。
- **SC-003**: 維運者建立一條阻擋規則後，該來源的請求在 5 秒內於所有服務副本上被拒絕。
- **SC-004**: 維運者的四種等效自鎖寫入路徑 100% 被攔阻；針對非自身來源的相同操作 100% 成功。
- **SC-005**: 自單一來源發動的輪換帳號名攻擊，在達到硬門檻後被鎖定；且在失敗序列中穿插任意次數的成功登入，**不會**使該來源的失敗計數歸零（此為守門測試，且刻意破壞該語意時測試必須轉紅）。
- **SC-006**: 登記為放行的來源，其失敗次數超過硬門檻時仍不被來源維度鎖定；未登記的私網來源則照常被鎖定。
- **SC-007**: 在信任設定壞損、規則資料不可讀、通知機制不可用、快取層故障、地理資料缺失等任一單點故障下，系統皆正常啟動且不拒絕任何本應放行的請求；每一次降級皆有對應的結構化告警。
- **SC-008**: 規則資料在服務執行期間發生一次瞬時讀取失敗後，判定面仍沿用上一份已知良好的規則集（阻擋與放行皆不失效）。
- **SC-009**: 登入嘗試稽核列的來源位址、信心、地理三欄反映真實還原結果；因來源維度短路的嘗試不產生稽核列。
- **SC-010**: 憑證換發與登出端點在超過速率上限時於應用層之前被拒絕；正常使用者的操作節奏 100% 不觸發。
- **SC-011**: 開發環境的登入請求路徑與正式環境同形（單跳、轉發鏈一元素），且正式建置產物可連通後端。
- **SC-012**: 本刀不新增任何錯誤碼、不新增任何資料表、不變更任何既有資料表結構。

## Assumptions

### 部署前提（未實測、承重）

- **DNAT 假設**：正式環境對外開放連接埠時，外部請求方的來源位址經核心層位址轉換後**被保留**，反向代理因此觀察到真實的傳輸層來源。此前提**未經實測**（本機開發環境為迴環開放，其觀察結果不可外推）。**若此前提被證偽**：反向代理附加的轉發標頭將全部落在內網段、被 Tier-2 跳過，還原結果全鏈退化為「回退」，來源維度的一切機制只看得到反向代理自己——存取控制閘本體仍有效但鍵到錯誤位址。補救路徑（改用主機網路模式、或關閉使用者態代理）記入部署刀檢查表。
- **CDN 網段清單為部署參數**：需維運定期更新。清單過期的後果為信心降等（fail-safe 方向、不誤放行）。
- **地理資料檔為部署資產**：其來源、校驗、存放策略、更新責任、以及地理欄的值形制（原文照存或正規化）留待 plan 拍板。

### 設計取捨（有意識接受）

- **共用出口內部的攻擊者可持續阻斷該出口的所有登入**：位於同一 NAT 出口的攻擊者（或受感染主機）可反覆打滿硬門檻，使該出口全體使用者被鎖；軟區驗證碼對在場的人類攻擊者僅是額外成本、手動解鎖後可立即被重新鎖上、且同出口的維運者本人亦被鎖。唯一止血手段為將該出口登記為放行規則——而放行即等同該出口**放棄**來源維度防護（輪換帳號名的攻擊面對該出口重新開啟，僅餘帳號維度）。候選改善（放行規則分型）另立待辦。
- **過寬的放行規則是單點繞過**：一條涵蓋大網段的放行規則使該範圍同時免疫全部阻擋規則、並完全跳過來源維度節流；集合語意無優先權、無信心下限、寫端亦不攔阻。候選改善（寫端最小化檢查、放行覆蓋阻擋的告警）另立待辦；部署檢查表須明列放行名單審視。
- **自鎖防護只覆蓋操作者當下的連線出口**：維運者自其他出口操作時，對某出口建立阻擋規則不受保護（此可能為合法意圖，例如封鎖已失陷網段，故不硬性攔阻）。
- **來源維度軟區對零失敗使用者可見**：帳號維度進入軟區前使用者自己已失敗數次、有自解釋脈絡；來源維度軟區則使同一出口上**從未失敗過**的使用者（含首次登入者）在第一次嘗試就被要求驗證碼，且依防枚舉原則不得解釋原因。此為有意識取捨。
- **門檻預設值的人口上界**：來源維度預設門檻假設單一出口背後的使用者規模上界；超過者應調高軟門檻或登記放行規則。大型共用出口在尖峰時段進入軟區屬**預期行為**（軟性、人類可通過），非罕見誤傷。
- **規則集失效時放行名單一併失效**：資料不可讀時退化為空集（僅限啟動初載），原本受放行豁免的來源將退回一般節流。

### 環境與驗收

- **開發環境對信任錨無區辨力**：開發拓樸下全部流量的還原位址收斂為同一常數、信心恆為「回退」；因此「三態區辨」類驗收在還原邏輯完全損壞時同樣會通過。信任錨的端到端行為只能以**構造轉發標頭**的方式驗證（經反向代理進入、模擬多個公開來源位址），此為本刀唯一具區辨力的實機驗收手段。
- **阻擋規則在開發環境無法直接驗證**：開發環境的還原位址落於私有網段（結構性豁免先放行），且對其建立阻擋規則會被自鎖防護拒寫；故阻擋驗收必須走構造轉發標頭的模擬來源。
- **CDN 驗證閘在開發環境零觸發面**：需以測試網段暫時覆蓋驗證閘設定才能驗證其標頭注入與信心升降；否則該鏈路要到正式環境掛上 CDN 當天才首次執行。
- **節流驗收具自傷性**：以真實共用桶打滿硬門檻會鎖住整個開發環境的登入直到時窗滑過，且快取標記不隨資料清理而消失。驗收必須以模擬來源進行，並具備復原手順。

### 既有資產（已核實）

- 來源位址規則的資料表、其有效唯一約束、實體對映、原型登記與凍結基準皆已存在於基線 ⇒ 本刀**零建表、零原型登記、零表數變更、零結構白名單**；唯一的資料變更為三個門檻設定的種子列（走既有的新增白名單機制、與其遷移同一提交）。
- 登入嘗試稽核的信心欄為不受限文字型別、無值域約束 ⇒ 七等級升級**零遷移**。
- 來源位址×時間的複合索引已備 ⇒ 來源維度計數的查詢底座現成。
- 節流快取的鍵形已將「維度」參數化並為來源維度留位 ⇒ 鍵形零改動。
- 規則管理五支端點的授權政策已於基線植入；★其中「刪除」政策的動作動詞與現行路由所支援的動詞集不相容——此衝突的解法（擴充動詞集／修正種子列）**留待 plan 拍板**，兩案的治理成本不對稱。
- 既有測試對信心欄的字面斷言將因七等級升級而失效，MUST 連動改寫。

### 治理與相依

- **憲法**：本刀為新行為島進場（判定序、真相分層與「真相暫不可讀時判定面沿用舊值」、全鏈 fail-OPEN 與唯一寫端例外、信任錨為來源維度一切機制之唯一輸入且信任集與跳過集同源對稱、放行跳節流只認顯式規則），以次要版本修訂入憲；入憲後 fail-OPEN 方向反轉為主要版本修訂。
- **既有行為島交互**：帳號維度節流的四項不變式 MUST 全數保持；其「判定鍵＝帳號名原文」之條文與本刀的來源維度並列判定需在入憲時同步釐清射程。
- **前刀 as-built 勘誤**（依既有紀律，後刀改變前刀行為時須回頭註記）：007 規格中「地理解析不做、地理欄維持恆空」與「不對憑證換發／登出端點設節流」兩處，由本刀兌現／補齊，MUST 於 007 規格補 as-built 勘誤註記。
- **wire 契約**：手動解鎖端點的請求形擴充（維度欄）屬既有端點的契約變更，MUST 有對應的契約案覆蓋。
- **前置批次**：開發環境反代拓樸修正（FR-041）為施工分段 P0，涉及前端受控檔案的首筆差異標記，需新增受授權軌道（憲法修訂、維運者親決）。其治理產物於 P0 完成時即提交，不延至收刀。
- **本刀規模**：預估 13~17 個執行單元，近既有最大先例之上緣。
