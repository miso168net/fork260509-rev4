## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登入者自助改密（驗舊密、撤他裝置） (Priority: P1)

任何已登入使用者（不限角色）進個人中心，於「修改密碼」卡選「舊密碼」驗證方式、輸入舊密碼＋新密碼＋確認新密碼後儲存：舊密碼正確且新密碼通過密碼政策→改密成功、本人**其他裝置的登入全部失效**（下次操作即被靜默登出）、當前操作裝置保留；成功提示明示「其他裝置已登出」。舊密碼錯誤、兩次新密碼不一致、新密碼違反政策→逐情境明確拒因（政策違規逐條列出哪裡不符）。

**Why this priority**: B-090 條目本體、ADR 0055 拆階段的兌現標的；B-030（首登強制改密）的前置依賴——本故事落地即解鎖。

**Independent Test**: 以非-super 測試帳號登入兩個裝置（兩個 session），於裝置 A 改密成功後：裝置 A 續用不中斷、裝置 B 下次請求被登出；舊密錯誤／政策違規各得對應拒因 toast。

**Acceptance Scenarios**:

1. **Given** 使用者持兩個有效 session，**When** 於其一以正確舊密碼改密且新密碼符合政策，**Then** 改密成功、成功提示含「其他裝置已登出」語意、當前 session 續存、另一 session 下次請求被靜默登出。
2. **Given** 使用者輸入錯誤舊密碼，**When** 儲存，**Then** 拒絕並提示舊密碼不符；密碼未變、任何 session 不受影響。
3. **Given** 新密碼違反政策多條（如長度不足＋缺大寫），**When** 儲存，**Then** 拒絕且 toast 逐條列出全部違規項。
4. **Given** 新密碼與確認新密碼不一致，**When** 儲存，**Then** 前端即時紅字提示；繞過前端直送亦被後端拒絕。
5. **Given** 使用者輸入與自己帳號相同的新密碼，**When** 輸入當下，**Then** 表單即時紅字提示（D4）；後端亦拒。

### User Story 2 - 登入者檢視與編輯個人資料 (Priority: P2)

使用者於「基本資料」卡見帳號、角色、建立／修改時間（唯讀、含來源語意標註：系統建立／管理員操作／本人未標註、未修改則明示）與暱稱、性別（可編輯）；於「信箱」「手機號」卡見綁定值輸入框。各卡獨立儲存、只更新該卡欄位；儲存成功即重新載入顯示最新值。

**Why this priority**: profile 自助檢視／編輯＝個人中心頁的基本盤；全頁承襲拍板的一部分，但價值次於改密主刀口。

**Independent Test**: 改暱稱單卡儲存→僅暱稱變、其他欄位不動、修改時間更新且標註為本人操作；帳號／角色欄不可編輯。

**Acceptance Scenarios**:

1. **Given** 使用者在基本資料卡改暱稱並儲存，**When** 重新載入，**Then** 暱稱更新、其他欄位（含信箱／手機）原值不動、修改時間更新且無操作者後綴（本人語意）。
2. **Given** 使用者在信箱卡輸入新信箱並儲存，**When** 重新載入，**Then** 僅信箱更新。
3. **Given** 帳號由系統 seed 建立，**When** 檢視基本資料卡，**Then** 建立時間帶「系統建立」後綴；從未被修改的帳號顯示「未修改」。
4. **Given** 任何登入者，**When** 檢視個人中心，**Then** 只見得到、也只改得動自己的資料（無任何指定他人身分的輸入面）。

### User Story 3 - 全頁 UI 承襲與人人可達 (Priority: P3)

個人中心版面與 rev3 成品完全一致：單欄縱排四卡（修改密碼→信箱→手機號→基本資料）、每卡右上儲存鈕、改密卡三種驗證方式單選（舊密碼預設／信箱驗證碼／手機驗證碼）、信箱與手機卡各帶「發送驗證碼＋驗證碼框＋驗證」佔位控件。驗證碼相關路徑一律提示「功能建置中」不送出（佔位非安全機制）。**任何角色**登入後點頭像下拉「個人中心」都能進頁（非-super 不再 404）。新密碼欄依現行密碼政策即時提示（政策由後端提供、任一登入者可讀）。

**Why this priority**: UI 全同＝user 拍板的硬約束；可達性（D1）是本頁「人人可用」語意的結構前提。獨立可測但不含寫入行為。

**Independent Test**: 以非-super 帳號登入→頭像下拉→個人中心正常進頁；四卡版面逐項對照 rev3 實機快照一致；點驗證碼類按鈕得「功能建置中」提示、零網路寫入。

**Acceptance Scenarios**:

1. **Given** 無任何選單授權的最小角色使用者，**When** 登入並點頭像下拉「個人中心」，**Then** 正常進頁（不 404）；其選單樹不因此多出任何管理頁。
2. **Given** 改密卡選「信箱驗證碼」或「手機驗證碼」，**When** 儲存，**Then** 提示「功能建置中」、不發送任何寫入請求；切換驗證方式時已輸入的憑證欄即清空。
3. **Given** 新密碼欄，**When** 輸入不符政策的值，**Then** 即時紅字提示（依現行政策動態生成規則）；政策僅密碼相關設定對登入者可讀、其他系統設定不可經此取得。
4. **Given** 四卡版面，**When** 與 rev3 實機對照，**Then** 卡序、卡形、欄位排列、按鈕位置、佔位控件逐項一致。

---

### User Story 4 - 介面三語化 (Priority: P4)

個人中心全部介面文字（卡標題、欄位、提示、拒因、成功訊息）支援 zh-TW／zh-CN／en-US 三語，切語系零 raw key；zh-TW 為在地化正體用語（儲存／信箱／手機號碼）、非簡體直轉。

**Why this priority**: rev4 三語紀律的例行兌現；獨立於功能行為可驗。

**Independent Test**: 三語系各切換一次，個人中心全頁與改密全流程（成功／各拒因）零 raw key、用語正確。

**Acceptance Scenarios**:

1. **Given** 語系 en-US，**When** 走完改密成功流程，**Then** 全部介面與提示為英文（含「其他裝置已登出」揭露句）。
2. **Given** 語系 zh-TW，**When** 檢視四卡，**Then** 用語為在地化正體（儲存、信箱、手機號碼）。

### Edge Cases

- 並發衝突：改密與管理員重設密碼／管理員刪除同帳號同時發生→序列化處理，後到者誠實拒絕（舊密已失效／帳號不存在），絕不假報成功。
- 本人帳號在操作期間被軟刪→讀端與寫端各依分工回應（讀端內部錯誤、寫端明確拒因），不洩漏他人資訊。
- 個人資料儲存送出空內容（無任何欄位）→零副作用（修改時間不得無故變動）。
- 性別欄收到值域外資料（繞過前端直送）→不寫入、既有值不動。
- 改密成功但登出廣播暫時失敗→他裝置仍在憑證換發時被擋（存活窗有上界）、不影響改密本身成功。
- 驗證碼佔位路徑被 crafted request 直打後端→後端契約僅認舊密碼路徑、無任何驗證碼通道可走。
- 政策設定被管理員即時調整→改密以儲存當下的現行政策為準（政策快照單點讀取）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供個人中心自助頁，任何已登入使用者可達（含無任何選單授權的角色）；可達性 MUST 為結構性保證（新建角色零配置即可達），且不得使任何管理頁面因此外洩到未授權角色的選單。
- **FR-002**: 個人中心版面 MUST 與 rev3 025 成品完全一致：單欄四卡（修改密碼→信箱→手機號→基本資料）、卡形／欄位排列／按鈕位置逐項復刻；驗證碼佔位控件三處照搬。
- **FR-003**: 自助改密 MUST 依固定順序驗證：帳號存在→兩次新密碼一致→舊密碼正確→新密碼通過密碼政策；任一步失敗即以對應拒因拒絕、密碼與 session 皆不變。
- **FR-004**: 密碼政策驗證 MUST 複用系統既有單一驗證點（與建帳、管理員重設共用、零分叉）；政策 MUST 以儲存當下單一快照讀取。
- **FR-005**: 改密成功 MUST 於同一原子操作內：更新密碼、撤銷本人全部其他 session（保留當前操作 session）、留存每筆撤銷的稽核事件與操作紀錄（密碼內容恆遮蔽）；完成後盡力即時通知他裝置登出，通知失敗時他裝置存活窗有上界（憑證換發時被擋）。
- **FR-006**: 改密成功提示 MUST 明示「其他裝置已登出」語意（D3）；政策違規拒因 MUST 逐條列出violations 明細（D2）；舊密碼不符與兩次不一致 MUST 為可區分的明確拒因。
- **FR-007**: 自助改密與個人資料操作的標的 MUST 恆為當前登入者本人（不採信請求內任何身分指定）；操作者紀錄＝本人。
- **FR-008**: 個人資料編輯 MUST 為部分更新：各卡只送自己欄位、未送欄位不動；可編輯欄僅性別、暱稱、手機、信箱四項（帳號、角色、時間唯讀）；空提交 MUST 零副作用；性別值域外輸入 MUST 不寫入。
- **FR-009**: 個人資料讀取 MUST 只回本人自有資料；建立／修改來源 MUST 折疊為三態語意（系統／管理員／本人）呈現、不洩漏操作者身分識別。
- **FR-010**: 密碼政策 MUST 對任一登入者可讀，且僅限密碼相關設定投影（鍵與值）；其他系統設定 MUST 不可經此讀取。
- **FR-011**: 新密碼欄 MUST 依現行政策即時提示（含「禁止與帳號相同」第 7 鍵、D4）；確認新密碼不一致 MUST 即時提示；前端提示為輔、後端驗證為權威。
- **FR-012**: 驗證碼相關 UI（改密卡兩驗證方式＋信箱／手機卡佔位控件）MUST 為純前端佔位：點擊提示「功能建置中」、不發送寫入；後端 MUST 不存在任何驗證碼通道（僅認舊密碼路徑）。
- **FR-013**: 個人中心全部介面文字 MUST 三語支援（zh-TW 在地化正體）、切語系零 raw key；文案鍵 MUST 走本頁專屬命名空間並維持型別鏡像機器一致。
- **FR-014**: 前端對上游基線既有檔的改寫 MUST 遵循 fork-delta 修改型 inline 紀律（原行逐字標記）；本刀新檔走新增型圈界。
- **FR-015**: 並發情境（改密 vs 管理員重設／刪除、資料編輯 vs 刪除）MUST 序列化處理且守門判定於鎖內重驗；標的消失或前提失效時誠實拒絕、絕不假報成功。

### Key Entities *(include if feature involves data)*

- **個人 profile**: 本人自有資料——帳號（唯讀）、角色（唯讀、代碼呈現）、暱稱、性別、手機、信箱（可編輯四欄）＋建立／修改時間與三態來源語意；既有使用者資料表完整覆蓋、零結構變更。
- **密碼政策投影**: 密碼相關設定的鍵值子集（7 鍵）；對任一登入者唯讀、供前端動態生成即時驗證規則。
- **Session（本裝置／他裝置）**: 改密時的撤銷標的——本人全部 session 減去當前操作 session；撤銷事件逐筆留痕。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 任一角色（含最小權限角色）登入後經頭像入口進入個人中心的成功率 100%（探索期實證非-super 為 404）。
- **SC-002**: 自助改密成功後，本人其他 session 於下次請求 100% 被登出；當前 session 100% 存續；此行為有自動化測試背書（拆除撤銷邏輯即紅）。
- **SC-003**: 改密拒因覆蓋率 100%：舊密錯、兩次不一致、政策違規（逐條明細）、帳號消失四類皆有明確且可區分的使用者提示。
- **SC-004**: 四卡版面與 rev3 實機快照逐項對照一致（卡序、欄位、按鈕、佔位控件零漂移）。
- **SC-005**: 三語系切換下個人中心全頁與改密全流程零 raw key。
- **SC-006**: 個人資料各卡部分更新零串擾：單卡儲存後其他欄位值 100% 不變；空提交零副作用（含時間戳）。
- **SC-007**: 密碼政策驗證與既有管理面共用同一驗證點（自動化測試證明拆分叉即紅）；系統其他設定經個人中心政策讀取通道外洩件數＝0。

## Assumptions

### 既有資產（已核實、2026-07-17 五鏡頭探索＋對抗審查）

- sys_user 欄集完整覆蓋 profile 四可編輯欄＋審計欄——零 migration、零 schema 變更；schema-gate 三閘不觸。
- `/user-center` 路由、頭像下拉入口、route 級三語值已在場；頁面現為上游基線 7 行佔位檔（修改型 inline 標的）。
- 密碼單一驗證點（ADR 0054）、keep-sid 撤 session 全形（011 reset_password）、他裝置登出前端管線（8888 靜默登出碼）、政策違規明細拒因＋violations 三語譯文全部現成可複用。
- 存取日誌絕不讀 body——改密請求明文密碼無入日誌風險。
- rev3 025 as-built 為受控參照（本機源倉、§I.5 不拷貝）；其已知坑清單（並發假報、confirm 規則快照、切換清憑證、空 body 時戳）已入 brainstorm §0.1 防重踩。

### 設計取捨（有意識接受）

- 驗證碼真流程（簡訊／郵件基建）不做——佔位 UI 照搬且明文「佔位非安全機制」。
- 舊密暴力試節流不做（攻擊前提＝已劫持 session；既有節流模組綁定登入流程不可直掛）——立 BACKLOG 追蹤。
- keep-sid 殘餘風險誠實記載：改密必收舊密＝session 劫持的既有防線；攻擊者兼知舊密時 keep-sid 非使能因子；復原路＝管理員重設密碼（全撤含攻擊者 session）。
- 清欄回 NULL 沿 rev3 不做；信箱／手機格式僅前端寬鬆驗證、與管理面同水位。
- 零 menu policy 角色登入後首頁兜底將落個人中心（新行為、屬改善）——測試明載。

### 治理（隨刀落地）

- ADR 0065（getUserRoutes 恆附掛 self-service 白名單）draft 已隨 brainstorm commit；plan 期 Constitution Check 復核 §III.2(g) 錨點並定案。
- 憲法 amendment 候選一筆：§III.2(g) 擴字串「＋對應 i18n key」（MINOR、照 013 v1.11.0 (d) 前例、plan 期定案）。
- 零新錯誤碼（全 2222 家族）、零新依賴；新拒因 i18n 鍵併 biz.user.* 既有域。
- changePassword 時序 MUST 合島 I1/I2/I5：鎖外驗舊密與計算雜湊、鎖內純比對重驗（絕不於持有鎖期間計算雜湊）、交易起手序列化鎖；update_own_profile 同鎖紀律（rev3 無鎖形不可照抄）。
