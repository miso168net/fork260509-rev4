## 背景

ADR 0016 保存了 rev3 021 刀的負快取層已驗證結論，並自述「節流本體的終態重設計＝B-010，本 ADR 保存快取層
已驗證結論供其引用（屆時如有調整走 supersede）」。007 為該終態設計，落地時發現 0016 的兩項結論需調整、
另有兩項不變式需明文追加（後兩者源自對抗式健全性審查的 blocker）。故以本 ADR supersede 0016。

## 決定

### 沿用 ADR 0016 的已驗證結論（不變）

- 對「已生效鎖定」在登入閘最前加 Redis 負快取，短路已鎖判定（命中即擋、零權威源查詢、零密碼雜湊）。
- **DB 維持鎖定真相**；負快取的存在**非權威**，絕不作為鎖定的真相來源。
- Redis 掛掉 **fail-OPEN**，退回 DB 滑動窗（節流仍生效、只是較慢）。
- **命中不續期**（refresh-on-hit ⇒ 攻擊者每 <TTL 戳一下即永久鎖死；rev3 已否決）。
- **鎖中命中不逐筆寫稽核**（量級改節流麵包屑進觀測層）；上鎖前歷程照寫——此為對「每終端結果恰一列稽核」
  的有意識反轉、非違規。
- 快取讀寫 key 由**同一 helper 導出**（防兩端渲染不一致靜默 miss；防法詳 ops/LESSONS）。

### 調整項一：TTL 由「固定 900 秒」改為「不長於時窗」

`實際 TTL = min(window_secs, THROTTLE_LOCK_TTL_SECS)`，其中 `THROTTLE_LOCK_TTL_SECS = 900`（活書常數）。

理由：0016 的固定 900s 成立於 rev3 的 `window` 為寫死 15 分（＝900s）之前提。007 將時窗開放為 runtime 可調
（`login_throttle_window_minutes`，1..1440），若仍固定 900s，則 `window < 15 分` 時負快取會**比權威源多鎖**
（L1 不查 DB）。

### 調整項二：雙維度 key 只啟用帳號維

0016 的「帳號／IP 雙維度 key」——**key 形保留**（單一 helper 導出、`dim` 參數化為未來 IP 維度留位），
但**只啟用 `user` 維**。IP 維度的啟用遞延 IP 閘刀：per-IP 節流的安全性 100% 由「防偽的真實來源位址」承擔，
rev4 尚無等值信任錨基建（詳 ADR 0037 §H.28、ADR 0017、B-019/B-024）。

★**helper 形制**（`[adr-amend]` 2026-07-10，釐清級；★本 ADR 的**決定不變**——key 形保留、`dim` 參數化留位、
只啟用 user 維）：key 由單一 helper `throttle_key(kind, dim, value) -> "throttle:{kind}:{dim}:{value}"` 導出，
其中 `kind ∈ {lock, unlock, suppressed}`、`dim` 現僅 `"user"`。原稿舉例的兩參數形 `throttle_dim_key(dim, value)`
**缺 `kind` 段**、渲染不出本層實際需要的三種 key——照字面實作會使鎖定負快取與解鎖標記產出同一把
`throttle:user:{name}`，令解鎖動作序（先寫標記、後清快取）退化為「同 key 寫後即刪」、標記永不存在。
權威形制以本段為準（發現於 007 `/speckit-analyze` 的 I1 finding）。

### 追加不變式一：負快取僅由「L2 再判路徑」寫入

失敗路徑本身**絕不**直接武裝負快取。0016 未言明寫入點，實作若讓「失敗路徑以其密碼驗證前讀到的舊 count」
武裝負快取，則一個並發的成功登入推進計數下界後，負快取會與權威源矛盾 ⇒ **假鎖**（懲罰剛登入成功的合法
使用者），且負快取短路使其在存活期內無法自癒。

現形之下負快取**恆衍生自一次新鮮的權威源讀取**（已含 reset-on-success 與解鎖標記兩個下界）⇒ 假鎖在構造上
不可能，島 E1「L1 其職僅短路已鎖判定」由宣稱變**恆真**。代價：鎖晚一個請求武裝，而那個請求本就會被權威源
擋下 ⇒ 負快取回歸純快取身分。

### 追加不變式二：sticky 退場——L2 再判路徑亦零稽核列

0016 只反轉了「L1 命中不逐筆寫稽核」，未涵蓋「L1 過期後 L2 再判鎖」路徑。**該路徑亦不得寫列。**

理由：時窗可調至 1440 分而負快取 TTL 上界 900s。若 L2 再判寫入 sticky 列，該列落入自身時窗 ⇒ 攻擊者每
~900s 一次探測即可無限續鎖；且該路徑排在 captcha gate **之前**，全程**免解題**。sticky 對安全零貢獻
（攻擊者本就被 L2 再判擋下），延長鎖只傷受害者——正是 B-018 惡意鎖人要治的病。

**鎖的存續純由真實失敗列在窗內決定、隨窗自然滑出而解除；鎖的最長存續＝一個時窗**（非負快取存活時間）。

### 誠實記載：軟區為未被負快取隔離的熱路徑

007 brainstorm 曾斷言「被錘的熱路徑已被 L1 隔離 ⇒ 讀放大不成立」——**該斷言錯誤**（對抗式審查 major 揭露）。
軟區（`captcha_after ≤ count < max_fails`）的缺-captcha 請求**永不計數、故永不上鎖、故永不被負快取短路**，
每發都走「1×解鎖標記讀 ＋ 1×設定查詢 ＋ 1×L2 count」。

誠實評估：①該路徑仍**比正常登入便宜**（argon2 ~百 ms 級主宰成本），非相對於無節流基線的退化；
②兩個 DB 讀皆走 index range scan、有窗下界；③真正的量級閘是 **nginx `limit_req`**（ADR 0037 §F.17）。
若量測顯示成問題，軟區決策負快取列為 BACKLOG 候選。

## 後果

- ADR **0016 轉 superseded**（`superseded_by` 由 `tools/docs-sync generate` 對稱回填）。
- 0016 後果節的遞延組（壓制告警規則／來源廣度估計／TTL 拆分＝B-033）**不受本 ADR 影響**，
  其中「可告警的結構化訊號」部分由 007 兌現（ADR 0037 §D.13），餘者續留 B-033。
- 「TTL 不長於時窗」與「僅由 L2 再判路徑寫入」兩項為**方向性面**，隨島 E1 入憲（§I.7）——反轉即 MAJOR。
- 「sticky 退場」使島 E3 的審計邊界得以寫成單一可驗證規則（ADR 0037 §C.10）。
