**Finding 001-1〔Important・spec_ref FR-007・覆核 CONFIRMED(high)〕**
`deploy/preflight-secrets.sh:15`——preflight 僅檢六機密、遺漏第七支 captcha_secret；與 generate-secrets（生七）
及 rust-api boot（驗七）不對稱，US4「up 前預檢指名缺檔」防呆對 captcha 失效。
detail：REQUIRED 陣列只含 postgres_password/redis_password/jwt_secret/refresh_token_secret/database_url/
redis_url 六支；但 generate-secrets.sh:87 已生成 captcha_secret、docker-compose.yml:60/70/155-156 掛載之、
config.rs:74 於 boot fail-loud 驗證之。後果：若 captcha_secret.txt 缺席，preflight 仍回「OK：六個必須 secret
檔齊備。可 up」而放行，缺檔要到 rust-api boot 才以 compose 空目錄殘骸的迂迴形式被抓——正是 US4/FR-007 要
消滅的誤導情境。另 :14 註解「與 generate-secrets.sh 同一份六機密清單」已成 stale。時序校準：captcha 由
007-login-throttle 加入、無 ADR 將其排除 preflight 範圍，屬 007 期漏補；SC-004『啟動階段指名攔截 100%』因
config.rs boot 仍指名 captcha 而未被打破，故非核心違規，但 FR-007/US4 的『預檢層』防呆保證確有缺件。
修法：REQUIRED 補 captcha_secret 並更新檔頭/註解為七機密。

**覆核判決（Fable 5・real=true・confidence=high）**：推翻失敗，finding 成立。證據：
①deploy/preflight-secrets.sh:15 REQUIRED 確僅六支（無 captcha_secret），:34 印「OK：六個必須 secret 檔齊備……可 up」，:14 註解「同一份六機密清單」已 stale；
②deploy/generate-secrets.sh:87 確生成 captcha_secret（檔頭 :2/:5-8 自稱七機密、明記「007 增」）；
③docker-compose.yml:59-60/70/155-156 確掛載 captcha_secret 並設 APP_CAPTCHA_SECRET_FILE；
④rust-api/server/src/config.rs:74 走 env_or_file，:4-21 缺檔/不可讀/空值/佔位值一律 panic 指名——故
captcha_secret.txt 缺席時 preflight 誤放行、缺檔延至 boot 才以 compose 空目錄殘骸形式被抓。
spec 面：specs/001-compose-stack/spec.md（US4 驗收2「缺一個機密檔→預檢失敗並指名」）、同檔
（FR-007「預檢命令在啟動前指名缺檔」）支持；加碼 quickstart.md（secrets 預檢節）明文「刪任一 .txt 重跑應指名缺檔」——刪
captcha_secret.txt 時 preflight 仍綠、直接違約。無 supersede：docs/arc42/decisions/ 全目錄 grep preflight
零命中，含 captcha 之 ADR（0029/0031/0034/0035/0037/0038/0040/0045）皆不涉 preflight 範圍；BACKLOG/LESSONS
無追蹤；007 spec.md（_FILE＋boot fail-loud 要求段）僅要求 _FILE＋boot fail-loud、tasks.md T004 未排 preflight 更新，屬 007 期漏補、
無任何明文排除。severity=Important 恰當：非 Critical（boot 層 panic 仍指名該機密、generate-secrets 可自癒
目錄殘骸、僅及 dev 環境）；非 Minor（preflight 唯一職責即枚舉必須機密，卻對第七支沉默並主動輸出錯誤的
